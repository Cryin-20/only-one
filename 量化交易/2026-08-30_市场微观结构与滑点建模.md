## 可复用原则（决策时引用）

1. **价差是流动性最便宜的代理**：流动性缺失的第一反应是 spread 扩大，再深一层才是 depth 塌缩；任何策略上线前先看 spread 与 depth 的常态分布。
2. **冲击跟交易量的平方根成正比**：跨品种、跨市场、跨周期都稳健成立；订单越大、单位冲击成本越低，但绝对成本越高——没有"小冲击大单"的免费午餐。
3. **滑点 ≠ spread**：spread 是可观察的瞬时成本，slippage 包含 spread + 临时冲击 + 永久冲击 + 时效漂移；回测只扣 spread 必然过度乐观。
4. **Kyle λ 衡量"信息含量"**：高 λ = 市场把订单流解读为信号越激进；同一笔订单在低 λ 环境下的冲击远小于高 λ。
5. **maker 是被动收入，taker 是显性支出**：费率套利的天花板由 maker 返点决定，地板由 taker 费决定；不区分 maker/taker 的成本模型一律错。
6. **24/7 ≠ 24 小时有深度**：加密"半夜"与"周末"的有效 depth 常只剩白天的 10-30%，异常行情时再叠一个数量级塌缩。
7. **流动性是脆性的**：单一交易所/单一品种/单一方向的集中度越高，在压力时段被 ADL、清算级联、提币暂停的概率越大。
8. **回测必须打"冲击折扣"**：Almgren-Chriss 模型给的是理论上界；实盘再 5-7 折是行业经验值（承自《架构初稿》L3）。

## 核心逻辑链

1. **前提**：策略期望收益都是按"假设在某中间价成交"算的；微观结构告诉你"你其实不能"。
2. **机制**：订单簿是流动性供给侧（限价单挂出）和需求侧（市价单消费）实时撮合的拍卖市场；spread 是即时性的价，depth 是体量上的量，λ 是被市场"读出来"的速度。
3. **结果**：扣除 spread → 扣除临时冲击 → 扣除永久冲击 → 扣除时效漂移 → 扣除 maker/taker 费 → 扣除返点 → 得到净 α；任一项低估都会被滑点反噬。
4. **策略天花板**：费率套利的理论上限 = 资金费率均值 × 持仓时间 - 往返成本；只要套利空间 > 0 就有正期望，但 0.005%/8h 这种级别的边际对成本极度敏感（项目 Phase 1 案例）。
5. **行动指引**：先量常态 spread/depth/λ 的历史分布定基线，再选 maker 主导的成交方式、再用 Almgren-Chriss 类模型拆单、再把"30 天均值开仓阈值"按 spread/impact 校准。
6. **风险回路**：压力时段 spread 跳升 × depth 塌缩 × λ 跳升 = 同一笔订单在危机下的成本是平时的 5-50 倍；这是策略爆仓的微观路径。
7. **决策口诀**：回测再漂亮，跑不过 spread × impact × funding net 的都是纸上 alpha。

## 分章笔记

### 第一章　订单簿数据结构与撮合规则

**1.1 订单簿（Limit Order Book, LOB）的基本结构**

订单簿是交易所维护的、当前所有未成交限价单的有序集合。买单（bid）按价格降序排列，卖单（ask）按价格升序排列；同价位按时间优先级（price-time priority）排队。

```
订单簿快照（XYZ）
==============================
最优买价（best bid）：$99.90  → 某买家愿意以 ≤99.90 买入
最优卖价（best ask）：$100.00 → 某卖家愿意以 ≥100.00 卖出
价差（spread）：       $0.10
中间价（midprice）：   $99.95

买盘（bids）                卖盘（asks）
$99.90  2,071 股           $100.00  1,152 股
$99.85  2,421 股           $100.05    972 股
$99.80  1,647 股           $100.10  2,155 股
$99.75  3,133 股           $100.15    732 股
$99.70  1,547 股           $100.20  3,037 股
```

**核心直觉**：spread 的存在不是因为"卖家贪婪"，而是因为**即时性（immediacy）是有价的**——挂限价单的人可以等待，所以赚 spread；下市价单的人要立刻成交，所以付 spread。

**1.2 行情数据的三个层级**

| 层级 | 内容 | 用途 | 加密典型 |
| --- | --- | --- | --- |
| **L1（Top of Book）** | 最佳买/卖价、最新价、成交量 | 实时报价展示、报价监控 | Binance/OKX `/ticker` 端点 |
| **L2（Depth）** | 最佳 ± N 档价格 + 各档累计量 | 中频策略、做市、冲击估算 | CCXT `fetch_order_book(symbol, limit=20)` |
| **L3（Full Depth）** | 每档每笔订单（含 order ID） | 微观结构研究、做市、queue position 估算 | 部分所支持（Binance WebSocket depth diff 流可重建） |

> **坑（承自 P0-3 数据管道踩坑）**：CCXT 的 `fetchOrderBook(symbol, limit=N)` 是 L2 而非 L3；Gate.io 的 `fetchOrderBook` 返回的是聚合后的档位（无 order_id），要做 queue position 估算只能自己用 WS 增量流重建（见 §1.5）。

**1.3 撮合规则：price-time 优先及其变种**

**默认规则（主流加密交易所）**：先按价格优先（bid 越高越先、ask 越低越先），同价位内按时间优先（先挂的单先成交）。

**变种**：
- **pro-rata**（部分期货交易所、大宗商品）：同价位按挂单量比例分配；适合做市但鼓励"挂大单"。
- **费率高者优先**（部分新兴交易所）：挂单者按 maker 费率高低排队，鼓励"挂 maker 单享返佣"。
- **size-time 混合**：先按 size 段再按 time，常见于订单簿薄的品种。

**1.4 订单类型与流动性方向**

| 订单类型 | 流动性角色 | 典型费率（VIP0） | 备注 |
| --- | --- | --- | --- |
| **Market Order（市价单）** | taker（消耗流动性） | taker 0.05%（Gate BTC 永续） | 立即成交，但吃 spread |
| **Limit Order（限价单）** | 可能 maker 也可能 taker | 看是否立即成交 | 挂在 best 上等成交 |
| **Post-Only Limit** | **保证 maker** | maker 0.02%（Gate）/ 部分所给返佣 | 若会立即成交则拒单；Binance/Gate 均支持 |
| **Iceberg / Hidden Order** | maker，但隐藏可见量 | 同 maker | 见 §1.5 |
| **FOK / IOC** | taker | taker | FOK = 立即全部否则撤；IOC = 立即部分成交余撤 |

**关键洞察**：**费率套利策略能用 Post-Only 就用 Post-Only**，这能把成交侧从 taker 切到 maker，单边费率从 0.05% 降到 0.02%（甚至负数，即返佣）。

**1.5 Iceberg / Hidden Order：被掩盖的 queue position**

Iceberg 单（冰山单）只对外显示"冰山一角"（visible portion），隐藏部分挂在同一价位但**优先级低于显示量**（多数所规则）。

**Trading 启示**：
- **挂单方**：用 iceberg 隐藏大单意图，避免被"front-run"，代价是成交优先级靠后。
- **吃单方**：L2 数据里看不到隐藏量，看到的 depth 严重低估真实供给——这是订单簿"塌陷"现象的微观根源之一。
- **检测方法**：观察同一价位反复出现同量级撤/挂单的 pattern，或用 L3 diff 流重建。

**1.6 queue position（排队位置）—— 做市策略的关键变量**

挂一笔限价单在 $100.00 ask 上，前面已经有 5,000 股；要成交就先吃掉那 5,000 股。**queue position = 在你之前排队的总量**。

**做市策略的盈亏拆解**：
```
做市利润 = spread 捕获 × 成交次数 - 逆向选择损失 × 成交次数
         = spread × fill_rate × T - adverse_selection × fill_rate × T
```
queue position 越靠前，fill_rate 越高，但被知情交易者反向吃的概率也越大；最优 quote 策略要在 fill_rate 与 adverse selection 之间权衡（Avellaneda-Stoikov 模型，详见第三章）。

### 第二章　买卖价差：结构与流动性度量

**2.1 spread 的三层定义**

| 名词 | 定义 | 用途 |
| --- | --- | --- |
| **Quoted Spread（报价价差）** | best ask − best bid | 最便宜的可观察流动性指标 |
| **Effective Spread（有效价差）** | 2 × \|成交价 − 成交时中间价\| | 衡量实际成交的"半 spread 成本" |
| **Realized Spread（已实现价差）** | 2 × \|成交价 − T 时刻后中间价\| | 衡量做市商在 T 窗口后捕获的 spread |

**直觉**：quoted 是"菜单价"，effective 是"实际付的半边"，realized 是"做市商事后看是否赚到"。三者关系是 quoted ≥ effective ≥ realized（因为部分 spread 流向了有信息优势的对手方）。

**2.2 Roll 1984 隐含价差估计**

Roll (1984) 经典结论：**在没有微观结构噪声假设下，成交价变化的一阶自协方差可以反推 spread**。

```
ΔP_t = P_t − P_{t−1}
Cov(ΔP_t, ΔP_{t−1}) = −s²/4     ⇒     s = 2√(−Cov(ΔP_t, ΔP_{t−1}))
```

**意义**：当只有 OHLC（开高低收）或成交价序列、看不到 order book 时，仍能从价格序列估计隐含 spread。**加密的可用性**：K 线是公开数据；做 8h/1d 周期的 spread 估算时 Roll 估计是合理起点。

**改进版**：Abdi & Ranaldo (2024) 的 CHL 估计器用 OHLC 而非仅 close，精度更高（在 1d/8h 颗粒度上比 Roll 准 30-50%）。

**2.3 Amihud illiquidity（非流动性比率）**

Amihud (2002) 提出：

```
ILLIQ_t = |r_t| / VOL_t
```

其中 |r_t| 是 t 期绝对收益率，VOL_t 是 t 期成交额。**直觉**：1 USDT 成交额推动了多少绝对价格变动——越大越 illiquid。

**加密用法**：用 5min 或 15min 颗粒度算 ILLIQ，做品种筛选（小币 ILLIQ 比大币高 1-2 个数量级）；监控 ILLIQ 时间序列突变可预警流动性事件（2025-10-10 BTC 顶部深度塌缩 90% 时 ILLIQ 跳升 50-100 倍）。

**2.4 Kyle's λ（价格冲击系数）**

Kyle (1985) 在连续拍卖 + 知情交易者 + 噪声交易者 + 竞争性做市商的设定下，推导出：

```
P = P_0 + λ · Q    （逆供给函数，λ 为 Kyle lambda）
```

其中 Q 是订单流（净买入量），λ 是做市商从订单流推断信息的速度。

**线性解的关键性质**：
- λ 与噪声交易波动 σ_ε **成反比**：噪声越大，做市商越难分辨信号，每单位订单流反应越小。
- λ 与信号方差 σ_v **成正比**：信号越强，做市商从订单流学到的越多，反应越大。
- 实证上：股票市场 λ 约 0.1-1.0% per 1% ADV，加密市场 λ 通常**更高**（BTC 约 0.3-1.5%，山寨币 1-10%）。

**为什么 λ 重要**：
- **执行成本**：一笔订单的市场冲击 ≈ λ × (Q/V)；λ 越大冲击越陡。
- **信号**：λ 跳升 = 市场认为当前订单流信息含量高 = 可能有"聪明钱"在动 = 跟随或反向的信号源。
- **NBER 实证（2024）**：λ 高的股票，机构投资者倾向于**把大单拆成小单在 λ 低时段**（信息含量低时段）执行。

**2.5 订单簿不平衡（Order Book Imbalance, OBI）**

```
OBI_n = (Σ_{i=1}^{n} V_bid_i − Σ_{i=1}^{n} V_ask_i) / (Σ_{i=1}^{n} V_bid_i + Σ_{i=1}^{n} V_ask_i)
```

n 通常取 5-10 档；OBI ∈ [−1, +1]，>0 表示买盘厚于卖盘。

**实证**：Cao/Hansch/Wang (2008, 2009) 在澳大利亚股市发现 OBI 在 20 分钟内有显著的短期收益预测力；Lee 的韩国市场研究确认 OBI 与同期收益正相关，且预测力可持续 5-20 分钟。

**加密应用**：
- **中频信号**：OBI 在 ±0.3 以上 + 突然放大 = 短期价格压力 → 套利/做市策略的输入特征。
- **预警**：OBI 极端值（>0.8）往往是大型 market order 即将到来的信号，但也可能接下来立刻反转。
- **坑**：OBI 是**截面**指标（某一刻的快照），不是时序累积；要和 imbalance momentum（OBI 变化率）合用。

**2.6 流动性度量在 Phase 1 费率套利的实操映射**

| 指标 | 用法 | 监控频率 |
| --- | --- | --- |
| Quoted Spread | 判断币种"流动性档位"（BTC/ETH/SOL/山寨） | 实时 |
| Effective Spread | 回测成本校准的实参 | 每日复盘 |
| Amihud ILLIQ | 币种白名单过滤（ILLIQ > 阈值禁做） | 周度 |
| Kyle λ | 异常冲击预警；执行拆单节奏 | 每 10min |
| OBI (n=5) | 中频信号特征（暂不直接驱动策略） | 实时 |

### 第三章　市场冲击模型：Almgren-Chriss 与平方根律

**3.1 Almgren-Chriss (2000/2001) 框架**

Almgren & Chriss 在 J. Risk 2001 上发表的"Optimal Execution of Portfolio Transactions"是执行算法的奠基性论文。**核心思想**：把大单执行建模为**市场冲击成本 × 时效风险**的均值-方差优化。

**模型设定**：
- 总持仓 X，要在 [0, T] 内平仓
- 价格动态（midprice）：
  ```
  dP̃_t = σ dW_t + γ d(X_t − X_{t−1})        ← 永久冲击（永久影响后续价格）
  ```
- 实际成交价：
  ```
  P_t = P̃_t + η · (X_{t−1} − X_t)/τ         ← 临时冲击（速率线性）
  ```
- 目标函数（mean-variance）：
  ```
  min  E[cost] + λ · Var[cost]
  ```

**两类冲击的物理意义**：
- **永久冲击 γ × Q**：你的交易向市场传递了信息，其他参与者据此调整报价（informed trading signal）；影响**交易结束后仍持续**。
- **临时冲击 η × v**：你为了即时成交支付的对价（流动性溢价）；影响**只在该笔成交上**，下笔恢复。

**最优执行轨迹**（标准解）：
- 不急（风险厌恶低 λ）→ 均匀慢卖 → 低冲击成本、高时效风险
- 急（风险厌恶高 λ）→ 前重后轻 → 高冲击成本、低时效风险
- **最优轨迹是一段前重后轻的指数曲线**，而非"TWAP 均匀"。

**3.2 平方根律（Square-Root Law）—— 实证最稳健的冲击规律**

Bouchaud 等人在 30 年内对多市场（股票、外汇、期货、加密）做 metaorder（拆单后的大单）的实证研究，发现了一个**异常稳健**的经验律：

```
Δp ≈ Y · σ · √(Q / V)
```

其中 Δp 是 metaorder 引起的平均价格变动，Y 是市场专属冲击系数（Y ≈ 0.5-2），σ 是日波动率，Q 是订单总量，V 是日均成交量。

**三条关键性质**：
1. **平方根而非线性**：1% ADV 的订单冲击远小于 10% ADV 订单冲击的 1/10（应该是 √(1%) ≈ 10%，√(10%) ≈ 31.6%）。
2. **波动率放大**：冲击与 σ 成正比——高波动期的同样订单，冲击比低波动期大。
3. **跨市场稳健**：股票、外汇、商品、加密都符合；常数 Y 大致同量级。

**与 Almgren-Chriss 的关系**：Almgren-Chriss 是线性冲击（理论上易处理），平方根律是实证规律（更贴近真实）。Gatheral (2010) 在"无套利"假设下推导出：如果冲击衰减是指数的，那么瞬时冲击函数必然是**平方根**形式——给实证规律提供了理论支撑。

**3.3 加密市场的特殊性**

| 因素 | 股票市场 | 加密市场 | 冲击影响 |
| --- | --- | --- | --- |
| 24/7 | 否 | 是 | 异常事件无收盘缓冲，单日"相当于"股票 3-5 天 |
| 涨跌幅限制 | 大多有 | 无 | 价格跳空（gap）是常态 |
| 链上确认延迟 | N/A | 几秒~几分钟 | 跨所对冲有"对冲窗口暴露" |
| 杠杆深度 | 受限 | 普遍 20-125x | 高杠杆放大 ADL、清算级联概率 |
| 价差深度比 | spread/depth 稳定 | 极端事件可跳 100x | 流动性脆性 |

**FTI 2025-10-10 案例的微观读数**：
> BTC 顶部 depth 当日缩水 >90%；价差从个位数 bps 跳到两位数 %；做市商要么大幅加宽 spread 要么直接撤单。

**含义**：常态校准的冲击参数，在压力时段要乘 5-50x 的 buffer。**费率套利策略在 -2% 日熔断触发时，滑点会比正常高 1 个数量级**——这正是为什么熔断要触发而不是"扛过去"。

**3.4 从 AC 到工程实操**

工程上不直接解 AC 的连续优化（数值不稳定 + 假设过多），常用两种简化：

**简化 1：TWAP/VWAP（最朴素）**
- 把订单均匀切分在 T 时间窗口内
- 优点：实现简单、避免一次性大单冲击
- 缺点：忽略市场微观结构（流动性在日内 U 形、U-shaped）

**简化 2：POV（Percentage of Volume）**
- 按目标成交占比（如不超过市场成交量的 10%）动态下单
- 优点：自适应市场节奏
- 缺点：可能因突发行情而无法成交（"没量"）

**项目 Phase 1 的选择**：费率套利不需要拆单——单边 50 USDT（约 0.0007 BTC）远小于任何一档 BTC 的 depth，**1 张 taker 市价单即可成交**。但仍要把"冲击参数"作为成本模型的输入，用于**回测中的成本建模**（详见第七章）。

### 第四章　滑点构成：固定 / 影响 / 时效三层分解

**4.1 滑点（Slippage）的标准三层**

```
Total Slippage = Spread Cost + Market Impact + Timing Cost
              = (s × f_s) + (price × volume_impact × ratio) + (drift over Δt)
```

**第一层：Spread Cost**
- 公式：S_spread = s × f_s
- s 是 quoted spread；f_s ∈ [0, 1] 是"吃 spread 的比例"（市价单 f_s=1，限价单 maker f_s=0）
- **不可消除**——只要吃单就付 spread

**第二层：Market Impact**
- 公式：S_impact = price × volume_impact_factor × (order_size / ADV)
- volume_impact_factor 是经验常数（约 0.05-0.2）
- 与订单大小、ADV、波动率正相关
- 平方根律版本：S_impact ∝ Y · σ · √(Q/V) × price

**第三层：Timing Cost（时效漂移）**
- 公式：S_timing = price × σ × √Δt
- 拆单时间窗口 Δt 内价格漂移的预期值
- **Almgren-Chriss 的关键 trade-off**：拆得越慢，时效成本越高、冲击成本越低

**4.2 一个简单的工程实现（参考 Stephen Diehl blog）**

```python
class SlippageModel:
    def __init__(self, vol_window=20, vol_impact_factor=0.1,
                 spread_factor=0.5, min_slippage_bps=1.0):
        self.vol_window = vol_window
        self.vol_impact = vol_impact_factor
        self.spread_factor = spread_factor
        self.min_bps = min_slippage_bps

    def estimate_slippage(self, price, order_size, adv, volatility=None, bid_ask_spread=None):
        base = price * (self.min_bps / 10000)
        volume_ratio = order_size / adv
        volume_impact = price * self.vol_impact * volume_ratio
        vol_impact = (price * volatility * self.vol_impact) if volatility else 0
        spread_impact = (bid_ask_spread * self.spread_factor) if bid_ask_spread \
                        else price * 0.001 * self.spread_factor
        return base + volume_impact + vol_impact + spread_impact
```

**4.3 加密场景的工程修正**

| 修正项 | 原因 | 推荐做法 |
| --- | --- | --- |
| 加入"网络延迟"项 | 跨所对冲在链上确认有 1-15s 延迟 | + delay_seconds × 1h σ |
| 区分现货 vs 永续 | 永续 spread 通常更窄、depth 通常更深 | 分别建模 |
| 加入 funding 窗口项 | 资金费率结算前后 1min spread 跳升 | + funding_window_buffer (e.g. +10% spread) |
| maker 返点作为负滑点 | post-only 成交享 80% 返点 | − rebate_rate × notional |

**4.4 "实际滑点 vs 预期滑点"的常见偏差**

| 偏差类型 | 方向 | 原因 |
| --- | --- | --- |
| **过乐观** | 实盘 > 预期 | 回测用了 taker 费率 + 零冲击；实盘有 funding 窗口跳价 |
| **过悲观** | 实盘 < 预期 | post-only maker 拿到了 spread 而非吃了 spread |
| **压力时段跳升** | 实盘 >> 预期 5-50x | 异常事件下 spread × impact 同步跳升 |

### 第五章　maker-taker 费率生态、返佣与结算

**5.1 maker-taker 费率模型**

主流加密交易所（Binance/OKX/Bybit/Gate/Bitget）采用 **maker-taker 双边费率**：
- **maker**：挂限价单等待成交，提供流动性 → 费率低/有返佣
- **taker**：下市价单立即成交，消耗流动性 → 费率较高

**典型费率（VIP0，常规档，2026 行情）**：

| 交易所 | Maker | Taker | 备注 |
| --- | --- | --- | --- |
| Binance | 0.02% | 0.05% | 现货深度第一；曾短暂 0 费率（2022.7-2023.3） |
| OKX | 0.02% | 0.05% | 高等级可达 maker 返佣 −0.005% / taker 0.015% |
| Bybit | 0.02% | 0.055% | 合约深度强 |
| **Gate.io** | 0.02% | 0.05% | 80% 返点（用户已确认）；资金费公式见架构初稿 |

**5.2 返佣机制：GT/Point/折扣券**

返佣是加密所的"用户忠诚度计划"，本质是**按交易量返还 maker 费**：

- **Gate.io GT 抵扣**：VIP 达标后用 GT（平台币）抵扣手续费，按市场汇率结算；80% 返点相当于 maker 0.02% × (1−0.8) = 0.004%。
- **Binance BNB 抵扣**：类似机制，BNB 折抵 25% 手续费（2026 年已是历史值，需查官网当前）。
- **OKX 等级返佣**：VIP4+ 可享 maker 负费率（你挂单成交后交易所倒贴）。

**5.3 费率对费率套利策略的"地板-天花板"效应**

**概念框架**（承自《架构初稿》Phase 1）：

```
策略净收益 = funding_collected − round_trip_cost
          = funding_collected − (spot_fee + perp_fee + slippage × 2)
```

| 项 | 无返点 | Gate 80% 返点后 |
| --- | --- | --- |
| 现货 taker 0.05% | 0.05% | 0.04% × 0.2 + 0.04% × 0.8 = **0.04%**（VIP0 taker 实际 0.05% × 0.2 = 0.01%），以实测为准 |
| 合约 taker 0.05% | 0.05% | 0.01% |
| 往返合计（50u+50u） | 0.05 USDT | 约 **0.05 USDT**（架构初稿已折算） |
| **盈亏平衡费率** | 0.007%/8h | **0.005%/8h** |
| **可做费率区间** | 0.007-0.03% | 0.005-0.03% |

**关键洞察**：返点的真正价值是**降低盈亏平衡线**，让 0.005-0.007% 这种"以前不划算"的中频费率变成可做。这是为什么 Gate 80% 返点对项目而言是决定性的。

**5.4 maker 优先的执行方式（post-only）**

费率套利的最优执行路径：
1. **建仓**：现货 post-only limit（maker） + 永续 post-only limit（maker） → 双边都享 maker 费率
2. **风险控制**：若 maker 单超时未成交（极端行情下 spread 扩大导致无法成交），撤单并改 taker —— 此时已接受"高成本但能成交"的兜底
3. **平仓**：同建仓逻辑

**工程实现要点**：
- post-only 单若会被立即成交则拒单（不要让它"误"成 taker）
- 设较短的超时（如 30s），超时未成交撤单
- 监控 maker 单的 fill_rate；fill_rate < 30% 持续 1h → 提示"挂单位置太靠后"

**5.5 资金费率结算窗口的"微观结构"**

资金费率每 8h（或 4h）结算一次。在结算前 1-2min：
- spread 通常扩大 10-50%（因为套利者抢单）
- depth 在结算后立刻恢复

**策略含义**：
- **不要在结算前 5min 内强平**——会被吃 spread × 2（开 + 平）
- **结算前后做 delta 再平衡**也要分时：现货 maker、永续 maker 错开 30s
- **极端费率反转**（如 30 天均值转负）清仓时也要避开结算窗口

### 第六章　加密 vs 传统：差异点与陷阱

**6.1 系统性差异对比**

| 维度 | 传统股票市场 | 加密市场 |
| --- | --- | --- |
| 交易时间 | 5×8h + 盘前盘后 | 24/7 无间断 |
| 涨跌幅限制 | 5-20% | 无（单日 -50% 常见） |
| 涨跌幅触发熔断 | 有（多级） | 无交易所级熔断 |
| 中央对手方（CCP） | 有 | 无（交易所直接对客户） |
| 结算 | T+1/T+2 | 实时（链上确认或内部记账） |
| 杠杆 | 受监管限制 | 普遍 20-125x |
| ADL 机制 | 无 | 普遍（自动减仓） |
| 跨市场价差 | 极小 | 显著（BTC 跨所 $20-100） |
| 钱地址标识 | N/A | 透明（链上） |
| 数据可得性 | 受监管机构管制 | 部分公开但格式不统一 |

**6.2 24/7 的双刃剑**

**优势**：
- 无开盘跳空 → 中频策略可以持续运行
- 全球资金流 → 跨时区套利窗口大
- 风险事件实时定价 → 没有"周末发酵"

**陷阱**：
- **凌晨深度塌缩**：UTC 02-10（亚洲深夜）BTC depth 常只剩白天 20-40%
- **周末流动性折价**：周五晚-周日 BTC spread 扩大 20-50%、OBI 噪声加大
- **无熔断保护**：传统市场的 circuit breaker 在加密中没有对应物
- **重要事件无时间缓冲**：监管公告、ETF 决议、黑客事件随时发生，无收盘"喘息"

**6.3 ADL（自动减仓）与清算级联**

**ADL 机制**：当强平账户穿仓（账户余额不足以覆盖亏损）且保险基金/对手方吃单无法完全覆盖时，交易所对**盈利方按层级**强制减仓。

**典型路径**：
1. 某大户 50x 做多 BTC
2. 价格快速下跌 → 触发强平
3. 强平单市价卖出 → 推动价格进一步下跌
4. 价格击穿下一批强平线 → 级联
5. 保险基金耗尽 → ADL 触发 → **盈利的 short 被强平**
6. 原本 delta 中性的费率套利组合 → **突然变成 delta 暴露**

**项目 Phase 1 风险**：
- 同所"现货多 + 永续空"**理论上不触发 ADL**（多仓在现货侧，不会被强平；空仓在永续但已锁定 delta）
- **但如果发生 -20% 暴跌**：现货侧的 50 USDT 跌到 40 USDT，永续空赚 10 USDT 抵消；但若交易所临时调整强平规则或 ADL 触发异常，net 风险不为零
- **Phase 1 风控的"日亏 -2% 熔断"** 实际上是为了在 ADL 触发**前**强制平仓——这是事后看最经济的止损点

**6.4 FTX 与 2025-10-10 案例的微观结构教训**

**FTX 崩盘（2022.11）**：
- 起因：客户资金被挪用
- 微观表现：FTT 价格暴跌 → Binance 宣布清仓 → 挤兑 → 流动性彻底蒸发
- 教训：**交易所本身可以成为对手方风险**（承自《架构初稿》L0：单一交易所资产 ≤ 50%）

**2025-10-10 加密闪崩**（FTI Consulting 复盘）：
- 起因：100% 关税威胁 + 高杠杆累积
- 触发：单一交易所 BTC depth 缩水 >90%；spread 从 <10 bps 跳到 >1000 bps
- 级联：unified margin 跨品种拖累 → ADL → 强平对冲基金盈利 short
- 关键数据：USDe 在 Binance 跌至 0.60 USDT（peg 失守），其他所仍接近 1.00
- **微观教训**：
  1. **单一品种的"全市场深度"是错觉**——流动性碎片化，单一 venue 即可触发全局崩溃
  2. **价格 oracle = venue 自身价格**是个系统性弱点（USDe 案例）
  3. **ADL 可以强平盈利对冲方**——费率套利组合的"安全 short"在 ADL 下不安全
  4. **不要把"对冲"当"无风险"**——对冲的对手方可能是同一交易所

**6.5 API 限速、节流与断连的工程含义**

**典型限速**（以 Gate 为例）：
- 公共行情：10-20 req/s
- 私有账户/下单：5-10 req/s
- WS 订阅数上限：通常 30-100 个频道

**工程要点（承自 P0-3 数据管道）**：
- 用 WS 而非 REST 拉行情（REST 限速快、WS 推送效率高）
- 订单/账户操作用 REST（WS 通常只读不写）
- 429 触发后指数退避；不要暴力重试（会被 ban）
- 心跳检测 + 断连自动重连 + 重连后**对账**（不要相信本地缓存的状态）

**6.6 加密独有陷阱速查**

| 陷阱 | 描述 | 防御 |
| --- | --- | --- |
| 插针（wicks） | 5min 内 -5% 然后回弹 | 风控的"近实时"必须 ≥1min 颗粒 |
| 交易所临时维护 | 提币暂停、撮合暂停 | 监控维护公告，触发"只平不开" |
| 链上 reorg | 几区块重组可能导致状态回滚 | 跨链桥等待更多确认 |
| 闪兑（flash swap） | 利用 DEX-CEX 价差的瞬时套利 | CCXT 部分支持但延迟敏感 |
| 预言机操纵 | 链上预言机被单笔大单操纵 | 多源 oracle 聚合 |
| 项目方砸盘 | 团队解锁一次性抛售 | 避开高解锁期 |

**7.1 Phase 1 策略的参数回顾**（承自《架构初稿》L5）

```
同所"现货多 + 永续空"，1x 隔离保证金
- 开仓条件：30 天平均资金费率 ≥0.01%/8h
- 目标区间：0.01-0.03%/8h
- 退出：连续 2-3 个结算周期转负 / 30 天均值转负
- 单币 ≤ 总资金 10%
- delta 偏离 >5% 再平衡
- 盈利预期（月净）：0.2-0.5 USDT（100 USDT 本金）
- 返点：Gate.io 80% 手续费返点
```

**7.2 微观结构对成本模型的修正**

**架构初稿已给的静态成本**（100 USDT 本金）：
- 现货返点后约 0.04%/次（以实测为准，CCXT 对 Gate 合约 calculate_fee 有 bug）
- 合约返点后 0.01%/次
- 往返总成本 ≈ **0.05 USDT**
- 盈亏平衡费率 ≈ **0.005%/8h**

**本条新增的微观结构修正**：

| 项 | 静态假设 | 微观结构修正 |
| --- | --- | --- |
| Spread Cost | 0（假设挂单 maker） | 0.005-0.02%（实测 Gate BTC 永续 spread 0.01-0.03%，吃单 + maker 单回撤） |
| Market Impact | 0（假设订单远小于 depth） | 已开仓 50 USDT < 0.001 BTC，远小于 1 档 depth，**实测应为 0** |
| Timing Cost | 0（同上） | 拆单窗口 <1min，几乎为 0 |
| Funding Window Risk | 未考虑 | 结算前 1-2min spread 跳升 ×2 → **避开结算窗口** |
| Rebate Rate | 80% 固定 | 实测账户 rebate rate 可能波动；以 config 注入 |
| Effective Fee | maker 0.02% | post-only 享 maker；非 post-only 拒单 |

**修正后的成本模型**：
```
往返成本 ≈ 2 × effective_fee + 2 × spread_cost + 2 × impact + funding_window_buffer
         = 2 × 0.01% + 2 × 0.02% + 0 + ~0
         = 0.06% × 50 USDT × 2
         = 0.06 USDT（保守，vs 架构初稿 0.05 USDT）
```

**修正后的盈亏平衡**：0.06 USDT / 100 USDT / 2 边 / 8h = **0.003%/8h**（vs 静态 0.005%）。返点让盈亏平衡线进一步下移。

**7.3 回测的滑点参数选择**

回测框架对单次成交的"扣费"应该包含：

```python
# 伪代码：每个 simulated fill 的扣费
def execution_cost(notional, is_market_order, exchange='gate'):
    base_fee_rate = 0.0001  # Gate 80% 返点后 maker 0.01%/taker 0.05%
    spread_cost_bps = 2.0   # 0.02% (实测 Gate BTC 永续 spread 中位数)
    impact_bps = impact_estimate(notional, adv, volatility)  # 平方根律
    
    if is_market_order:
        fee = notional * (0.0005 * 0.2)  # taker 0.05% × 20% (无返点部分)
        spread = notional * spread_cost_bps / 10000
        impact = notional * impact_bps / 10000
    else:  # post-only maker
        fee = notional * (0.0002 * 0.2)  # maker 0.02% × 20%
        spread = 0  # maker 不付 spread
        impact = 0  # 挂单者不冲击
        
    total = fee + spread + impact
    return total
```

**回测审计要点**（承自架构初稿 L3）：
- 检查所有成交都扣了"≥2 层成本"（不只扣 fee）
- funding 收支按结算时刻严格计入（不漏结算周期）
- 退场时同样扣完整成本（很多回测只扣入场）
- 参数扫描：把 spread_cost_bps 从 1 扫到 10，看策略是否仍然正期望

**7.4 Gate.io 80% 返点后的 taker 实际成本**

**重要提醒（承自架构初稿 P0-3 已知坑）**：
- CCXT 对 Gate 合约 `calculate_fee` 有 bug（taker 费可能返回 0）
- 实测费率需自己从 `markets` 读取或手填（VIP0 合约 maker 0.02%/taker 0.05%）
- freqtrade 对 Gate 的 POINT 支付会自动按 fee=0 计算失败

**工程方案**：
- 在 `config/fees.yaml`（或 `risk.yaml` 内）手填 maker/taker 基础费率
- 80% 返点以**变量**形式注入（账户等级变化时改这个变量即可）
- 不依赖 CCXT 的 fee 计算

```yaml
fees:
  exchange: gate
  spot:
    maker_bps: 2.0
    taker_bps: 5.0
  perp:
    maker_bps: 2.0
    taker_bps: 5.0
  rebate_rate: 0.80  # 80% 返点（需按账户实测调整）
  effective_maker_bps: 0.4   # 2.0 × (1 - 0.8)
  effective_taker_bps: 1.0   # 5.0 × (1 - 0.8)
```

**7.5 1x 隔离保证金 + 现货多 + 永续空的成交细节**

**建仓顺序（最优）**：
1. **先永续空（post-only maker）**——先锁定 funding 的"收钱腿"
2. **再现货多（post-only maker）**——再锁定 delta 的"对冲腿"
3. 两边都成交后，组合就锁定了 funding rate 净收益 + delta 中性

**理由**：
- 如果先现货多、未平永续空：会暴露"无对冲的现货"风险（即使短窗口）
- 如果先永续空、未平现货多：会暴露"无对冲的永续空"风险（funding 收取方向但裸 delta 暴露）
- "两边同时成交"在 maker 模式下不现实（post-only 不保证即时成交）

**最坏情况**：第一腿成交、第二腿未成交（market order 也吃不进）→ 立即触发熔断评审，**人工**决定是否用 taker 强补第二腿 + 记录事件。

**7.6 Funding rate 入场时机与冲击脱钩**

**常见误区**：以为"费率越高越好"，拼命追 ≥0.05% 极端费率。

**微观结构洞察**：
- 极端费率（≥0.1%/8h）通常是**短期失衡**（如新币上线、L2 升级），很快均值回归
- 在极端费率入场 = 在"资金费率交易最拥挤"的时刻入场 → **冲击成本被推到极高**
- **正确入场窗口**：费率刚回升至 30 天均值以上（0.01-0.03%）时，spread 仍窄、对手盘还没反应过来

**架构初稿已定的目标区间 0.01-0.03%** 与上述洞察一致——本条为其提供了微观结构层面的解释。

**7.7 风险事件触发的"微观应急预案"**

## 自测

1. **（订单簿基础）** 在 99.90/100.00 的报价上，**中间价是多少？** 若以市价单买入 1,000 股，effective spread 是多少？
2. **（流动性度量）** Roll (1984) 估计 spread 用的是哪个统计量？若你只有 8h K 线（OHLC）数据而无 order book，应优先用哪个改进版估计器？
3. **（市场冲击）** Almgren-Chriss 模型的永久冲击与临时冲击在物理意义上有什么区别？为什么 AC 用线性（而非平方根）冲击假设，工程实操却常用平方根律？
4. **（Kyle λ）** 在 λ = 0.5% per 1% ADV 的市场，下一笔 0.5% ADV 的订单预期冲击是多少？若订单拆成 10 笔每笔 0.05% ADV，冲击会变小还是变大？为什么？
5. **（费率套利）** Gate 80% 返点后，合约 taker 实际费率从 0.05% 降到多少？若套利空间 = 资金费率均值 0.008%/8h，开仓/平仓各 1 次往返纯费率成本后是否还有正期望？
6. **（加密微观结构）** ADL 是什么？为什么 delta 中性的费率套利策略"理论上不触发 ADL"但在极端行情下仍可能受影响？
