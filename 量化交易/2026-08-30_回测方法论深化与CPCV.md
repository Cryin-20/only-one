## 可复用原则（决策时引用）

1. **回测数字一律按"已假设过拟合"打折**：McLean & Pontiff 2016 实证样本外收益平均下降 26%、发表后下降 58%；社区经验值实盘劣化 30-50%。任何漂亮回测 = 默认减半起步讨论。
2. **单一 train/test 切分 = 隐性作恶**：只把数据切成两段，就只能告诉你"这一次运气好不好"，无法估计"我试了多少次才找到这次好运"——任何 5+ 参数、20+ 候选的策略必须升级到多重检验框架。
3. **PBO 回答的是"我试了几次"而不是"这一次对不对"**：Bailey-Borwein-López de Prado-Zhu 2014 的 Probability of Backtest Overfitting = "在 N 次候选里，is-best 在 OOS 跌出中位以下的概率"——这是把"过拟合"从形容词变成可计算概率的奠基性贡献。
4. **DSR 修正多重检验下的 Sharpe 显著性**：Bailey-López de Prado 2014 的 Deflated Sharpe Ratio = "在 N 次候选里，最佳 Sharpe 超过 null 期望最大 Sharpe 的概率"——同时修正 selection bias + 非正态 + 自相关。
5. **CPCV 是当前最强防过拟合武器**：López de Prado 2018 第 7 章给出，从 N 组数据选 k 组做 test、剩余做 train 的全部组合（C(N,k) 条路径），每条路径算 Sharpe，最终给"概率性 Sharpe ≥ X"的 p-value——Sciencedirect 2024 实证对比 K-Fold/Purged K-Fold/Walk-Forward/CPCV，CPCV 在 PBO 和 DSR 双指标上显著占优。
6. **purging + embargo 是工程级防泄漏硬要求**：金融数据的标签（label）窗口跨 bar 意味着即使 train/test 切分对，某些 train 样本的"未来信息"仍会通过 label 泄漏到 model；purging 删重叠、embargo 加 buffer 是 defacto standard。
7. **walk-forward 不是越多次越好**：一次 walk-forward = 一次假设检验；多次 walk-forward 仍然只是多次假设检验，没有多重检验修正——所以 walk-forward 必须和 PBO/DSR 并用，不能单跑。
8. **蒙特卡洛必须配块状 bootstrap**：加密收益序列自相关极强（BTC 日收益 lag-1 自相关 0.05-0.15、绝对收益 lag-1 自相关 0.3-0.5），iid bootstrap 会低估尾部；块状（block）或 stationary bootstrap 是金融时间序列的唯一合理选择。

## 核心逻辑链

1. **前提**：单一 train/test 切分的回测在 N 次参数扫描后，必然选出"在 test 上偶然跑赢"的参数——这就是"过拟合"的真实含义；不是模型"记住了"数据，而是"我们记住了"让我们以为模型赢的切片。
2. **机制**：多重检验 + iid 假设 + 自相关 + 标签泄漏 + 微观结构偏差 → 任何标准回测数字都是"经过过筛的运气值"——要把它还原成"真实的策略价值"，需要四件工具同时上阵：PBO（多少倍过筛）、DSR（多少倍赢是 null 期望之上的）、CPCV（如何从多重 backtest 推 p-value）、蒙特卡洛（路径分布而非点估计）。
3. **结果**：CPCV 给出"策略 Sharpe ≥ X 的概率"的 p-value（与 t 检验的 p-value 同形式但语义更宽）；PBO 给出"is-best is overfit"的对偶概率；DSR 把"单一 Sharpe 检验"修正为"在 N 次选择后的 Sharpe 检验"——三者口径不同、互补。
4. **行动指引**：上线任何策略前，至少跑 5 关上强度检查：① purged k-fold + embargo 检查标签泄漏 ② CPCV 算 PBO/DSR ③ walk-forward 多周期滚动 ④ 块状 bootstrap 蒙特卡洛 ⑤ 反向压力测试找脆弱性——五关全绿才进入 paper trading。
5. **加密特殊性**：加密收益非平稳、厚尾、自相关强、清算级联 + 24/7 无熔断——标准回测的 5-7 折经验值在加密里要再加 30-50% buffer（BTC 日收益峰度 20+，参数法 VaR 99% 覆盖率实测只有 80-90%）。
6. **本项目映射**：Phase 1 费率套利的"上强度"回测流水线 = 上面 5 关上强度检查的具体实现 + 100 USDT 体量下的"算力/价值"权衡——CPCV 全 C(N,k) 路径扫描在加密高频数据上计算量可观，**用 N=6、k=2 的 15 条路径 + 50 次蒙特卡洛**是性价比拐点。
7. **决策口诀**：回测强度 ≥ 策略新颖度；样本外不打折的不要信；蒙特卡洛不信的不要实盘；五关上强度检查全绿才准跑——少一关就降级观察。

## 分章笔记

### 第一章　回测方法论演进史（从 in-sample 到 CPCV）

**1.1 单一 in-sample 回测（1980s-1990s 主流）**

最朴素的做法：把全部历史数据"拟合"出一个策略（参数、规则、阈值），报告它在历史数据上的夏普、回撤、年化。

**致命问题**：
- 参数个数 ≥ 5 时，几乎必然"记住"历史噪声
- 没有样本外概念，谈不上"未来是否有效"
- 实证证据（Bailey-Borwein-López de Prado-Zhu 2014 AMS Notices）：**只需 2-5 个参数 + 250 个候选配置 + 1000 个样本日 = PBO > 50%**——意味着"挑出来的最佳配置"过半概率是过拟合

**今日定位**：仅适合做"概念验证（PoC）"的第一步，**绝不能用作策略上线的依据**。

**1.2 简单 train/test 切分（2000s 主流）**

把数据切成 70/30 或 80/20：前段做参数选择（in-sample / IS），后段做样本外验证（out-of-sample / OOS）。

**改进点**：
- 引入了"未见过"的样本概念
- OOS 夏普是对 IS 夏普的"现实折扣"

**仍然不够**：
- **一次性假设检验**：只跑一次 OOS，无法估计"我试了多少次才挑中这一组参数"
- **无多重检验修正**：如果我在 IS 上跑了 50 组参数，选了 OOS 上最好的——那"这次好"还有多大意义？
- **regime 失效**：IS 和 OOS 处于同一 regime 时估计合理；但市场结构变化后 OOS 的预测力迅速衰减

**1.3 Walk-Forward Optimization（WFO，2010s 起主流）**

把数据切成 N 个滚动窗口；每个窗口内 IS 调参 → OOS 验证 → 滚动一步 → 重复。汇集所有 OOS 段的 P&L 得"walk-forward equity curve"。

**两种主流变体**（承自 SusanPotter.net / AronGroups 解读）：

```
Anchored (Expanding) Walk-Forward：
Step 1:  [===TRAIN===][TEST]..............
Step 2:  [=====TRAIN=====][TEST]..........
Step 3:  [========TRAIN========][TEST]....
Step 4:  [==========TRAIN==========][TEST]

Rolling (Fixed) Walk-Forward：
Step 1:  [===TRAIN===][TEST]..............
Step 2:  ....[===TRAIN===][TEST]..........
Step 3:  ........[===TRAIN===][TEST]......
Step 4:  ............[===TRAIN===][TEST]..
```

**Anchored vs Rolling 的取舍**：
- **Anchored**：保留所有历史，适合长期趋势 / 长记忆策略；但若 regime 切换过（如 2020-03 之后加密市场结构变化），旧数据会"拖累"估计
- **Rolling**：固定窗口长度，自适应最近 regime；但样本量受限，参数估计方差大

**Susan Potter 建议**：跑两种——如果两种都过 walk-forward，证据强；只过一种，证据中等。详见第四章。

**WFO 的根本局限**：本质仍是"多次单假设检验"，**没有修正"我跑了多少次"的多重检验**——一篇 SSRN 工作论文对比 KFold / Purged K-Fold / Walk-Forward / CPCV 后发现，**Walk-Forward 的 PBO 中位数最高**（即最容易过拟合），CPCV 最低。

**1.4 Combinatorially-Purged K-Fold CV（CPCV，2018 起，AFML 第 7 章）**

**López de Prado 在 *Advances in Financial Machine Learning* (2018) 第 7 章给出的方法**（O'Reilly 公开章节预览确认）：
1. 把时间序列切成 N 个有序组（groups）
2. 从 N 组里选 k 组做 test（C(N,k) 种选择）
3. 剩余 N-k 组做 train
4. **每种选择 → 1 条 backtest 路径**——总共 C(N,k) 条路径
5. 对每条路径施加 purged k-fold 的 purging + embargo
6. 在每条路径上算 Sharpe，把所有路径的 Sharpe 排序做分布估计
7. 给"Sharpe ≥ X"的 p-value（经验分布的分位数）

**为什么是当前最强**：
- **多重 backtest** 而非单次 → 直接估计"策略在不同 regime 下的稳健性"
- **purged + embargo** → 解决金融数据的标签泄漏
- **概率性输出**（p-value）而非点估计 → 可以做"是否上线"的二元决策

**1.5 多周期 CPCV（multi-horizon）**

对同一策略在不同时间窗口（1m / 5m / 15m / 1h / 4h / 1d）分别跑 CPCV，验证策略在不同 horizon 下都过 PBO/DSR 检验——防止"只在某个特定 horizon 上偶然过拟合"。

**1.6 演进史的一页纸总结**

| 方法 | 年代 | 核心优势 | 核心缺陷 | 适用场景 |
| --- | --- | --- | --- | --- |
| **In-sample** | 1980s | 简单 | 完全过拟合 | 概念验证 |
| **Train/Test 切分** | 2000s | 有 OOS 概念 | 单次检验、无多重修正 | PoC 升级 |
| **Walk-Forward** | 2010s | 模拟实盘滚动 | 多重检验未修正、PBO 最高 | 日常实盘迭代 |
| **Purged K-Fold** | 2018 | 防标签泄漏 | 仍是单路径 | 任何 ML 策略 |
| **CPCV** | 2018 | 多重 backtest + p-value | 计算量 O(C(N,k)) | 终审级别 |
| **多周期 CPCV + MC + RST** | 2020s | 立体防御 | 工程复杂 | 战略级策略 |

**关键洞察**：从 in-sample 到 CPCV 是"假设检验"的成熟度跃迁——从单点估计到分布估计、从单次到多重、从"是否盈利"到"在多重检验下盈利的概率"。

### 第二章　PBO 与 Deflated Sharpe 回顾（Tier 1 论文摘要）

> **Tier 声明**：本章基于 Bailey-Borwein-López de Prado-Zhu 2014 的 *Probability of Backtest Overfitting*（J. Computational Finance 20(4) 2017；SSRN 2326253）、Bailey-López de Prado 2014 的 *Deflated Sharpe Ratio*（J. Portfolio Management 40(5)；SSRN 2460551）的论文摘要、quantresearch.org 官方发表列表及 ResearchGate / Risk.net 公开页面。**未直接读论文全文**，公式形式以 Wikipedia 与 QuantInsti 二手转述交叉验证。

**2.1 PBO（Probability of Backtest Overfitting）的一句话定义**

> 在 N 个候选策略配置中，"in-sample 最佳"在 OOS 上跑输中位（bottom half）的**经验概率**。
>
> —— Bailey, Borwein, López de Prado, Zhu (2014)

**直觉**：PBO 回答"我挑出来的'最佳'策略有多少概率是过拟合的"——PBO = 0.5 表示"和掷硬币无异"，PBO = 0.9 表示"基本确定是过拟合"。

**2.2 CSCV（Combinatorially Symmetric Cross-Validation）：PBO 的实现方法**

CSCV 是 PBO 的工程实现（Bailey 2014 提出）：
1. 把 N 个候选配置的收益序列拼成 T × N 矩阵（每行一个时间点，每列一个候选配置）
2. 把行切成 S 组（default S=16）
3. 遍历所有"选一半做 train、一半做 test"的 C(S, S/2) 种切分（对称切分）
4. 每种切分中：
   - 找出 in-sample 表现最佳的候选（log-likelihood / Sharpe / 用户指定的目标 F）
   - 看它在 out-of-sample 的相对排名（是否 ≥ 中位 = rank T/(S/2)）
5. **PBO = "is-best OOS 排名 ≤ 中位"的切分占比**

**CSCV 的关键性质**（承自 Bailey 2014 + Risk.net 公开摘要）：
- **不需要分布假设**：纯非参数
- **可处理任意目标函数**：Omega ratio、Sharpe、Sortino、Calmar 等都可
- **对称性保证**：切分的对称设计让 in-sample 和 out-of-sample 的样本量均衡

**Bailey 2014 的关键定理**：
> 在 N 个候选配置 + 任意 S 下，CSCV 的 PBO 估计随 N → ∞ 收敛到 1——**即"参数搜索足够多就必然过拟合"，与单个配置的预测力无关**。

**对工程的意义**：
- 5 个参数 × 3 个候选值 = 243 配置组合
- 加上出场规则、止损规则、仓位规则的离散化 → 实际"配置"数轻易破千
- **不报告 PBO 的回测报告 ≈ 自欺**

**2.3 DSR（Deflated Sharpe Ratio）的一句话定义**

> 在 N 个候选策略中，"观察到的最佳 Sharpe"超过"null 假设下的最大 Sharpe"的**经验概率**——同时修正 selection bias + 非正态 + 自相关。
>
> —— Bailey & López de Prado (2014)

**直觉**：你跑 200 组参数、选出 Sharpe 1.8 的"最佳"——但 null 假设下 200 次独立抽样的最大 Sharpe 期望值约 = √(2 ln 200) ≈ 3.4。所以"1.8"在 null 下其实是显著低于期望——**Sharpe 1.8 不是 200 次里的"显著赢家"，反而是"低于 null 期望的输家"**。

**2.4 DSR 的核心公式**

**null 假设下 N 次试验最大 Sharpe 的期望**（Bailey-López de Prado 2014 公式 4）：
```
E[max SR] ≈ (1 − γ) · Φ⁻¹(1 − 1/N) + γ · Φ⁻¹(1 − 1/(N·e))
```
其中 γ ≈ 0.5772（Euler-Mascheroni 常数），N 是试验数。

**Probabilistic Sharpe Ratio（PSR）**（前置概念）：
```
PSR(SR*) = Φ[ (SR̂ − SR*) · √(T − 1) / √(1 − γ₃·SR̂ + (γ₄−1)/4 · SR̂²) ]
```
其中 SR̂ 是观测 Sharpe、SR* 是基准 Sharpe、T 是样本数、γ₃/γ₄ 是偏度/峰度。

**DSR = PSR(SR* = E[max SR | null])**：把 SR* 替换为"null 假设下 N 次试验最大 Sharpe 的期望"。

**关键洞察（DSR 的修正式）**：
```
DSR ≈ Φ[ (SR̂ − E[max SR | null]) · √(T − 1) / √(1 − γ₃·SR̂ + (γ₄−1)/4 · SR̂²) ]
```

修正项 (1 − γ₃·SR̂ + (γ₄−1)/4 · SR̂²) 同时吸收：
- **非正态**（偏度 γ₃、峰度 γ₄ 偏离正态时放大分母）
- **自相关**（T 替换为有效独立样本数 = T · (1−ρ)/(1+ρ)，ρ 是 lag-1 自相关）

**2.5 实战：DSR 的 Python 计算框架**（承自 paperswithbacktest.com 实现 + QuantInsti 教程）

```python
import numpy as np
from scipy.stats import norm

def expected_max_sr(n_trials, sr_std=1.0):
    """Null 假设下 N 次试验最大 Sharpe 的期望（Bailey-López de Prado 公式）"""
    emc = 0.5772  # Euler-Mascheroni
    z = np.sqrt(2 * np.log(max(n_trials, 2)))
    e_max = z * (1 - emc / (2 * np.log(max(n_trials, 2)))) + emc / z
    return e_max * sr_std

def deflated_sharpe_ratio(observed_sr, sr_benchmark, t_obs, skew=0, kurtosis=3):
    """
    observed_sr: 候选集中的最佳 Sharpe（年化）
    sr_benchmark: null 下期望最大 Sharpe
    t_obs: 观测样本数（用有效独立样本数更准）
    skew/kurtosis: 收益分布的偏度/峰度
    """
    sr_diff = observed_sr - sr_benchmark
    denom = np.sqrt((1 - skew * observed_sr + (kurtosis - 1) / 4 * observed_sr**2) / (t_obs - 1))
    z = sr_diff / denom if denom > 0 else 0
    return float(norm.cdf(z))

# 示例：试 200 组参数、最佳 Sharpe 1.8、3 年日数据
n_trials = 200
t_obs = 756  # 3 年 × 252 日
best_sr = 1.8
benchmark = expected_max_sr(n_trials)  # ≈ 3.4
dsr = deflated_sharpe_ratio(best_sr, benchmark, t_obs, skew=-0.3, kurtosis=4.5)
# 结论：DSR < 0.05 → "Sharpe 1.8 不显著"
```

**2.6 PBO vs DSR 的关系与互补**

| 维度 | PBO | DSR |
| --- | --- | --- |
| **目标** | is-best OOS 跌出中位的概率 | is-best Sharpe 超过 null 的概率 |
| **输入** | N 配置的 OOS 相对排名 | N 配置的 Sharpe + 分布形状 |
| **输出** | 标量 PBO ∈ [0, 1] | 标量 DSR ∈ [0, 1]（p-value 含义） |
| **对参数的依赖** | 弱（只关心排名） | 强（依赖偏度/峰度） |
| **适用场景** | 多重配置后"选哪个"的诊断 | 单次 Sharpe 报告的显著性判断 |
| **结合使用** | PBO 高 + DSR 低 = 双重过拟合警报 | |

**2.7 Bailey-López de Prado 2014 的金融业实证**

承自 Bailey & López de Prado 2021 *Significance* 18(6) 的公开摘要：
> "投资机构付钱让研究员发论文推广可疑策略——这些论文几乎从不控制多重检验。今天的学术金融有点像 1950-2000 年间的医学界（Big Tobacco 付费发支持烟草的研究）。"

### 第三章　Combinatorially-Purged K-Fold Cross-Validation（CPCV，必含）

> **Tier 声明**：本章基于 López de Prado 2018 *Advances in Financial Machine Learning* 第 7 章"CPCV Addresses Backtest Overfitting"（O'Reilly 公开章节预览 https://www.oreilly.com/library/view/advances-in-financial/9781119482086/c07.xhtml）+ Reasonabledeviations 读书笔记 + QuantInsti 系列博文 + stats.stackexchange 讨论 + `skfolio.model_selection.CombinatorialPurgedCV` 源码注释 + ScienceDirect 2024 "Backtest overfitting in the machine learning era" 实证论文交叉验证。**未直接读 AFML 第 7 章全文**——公式形式以开源实现 + 读书笔记交叉验证。

**3.1 CPCV 的一句话定义**

> 把时间序列切成 N 个有序组，从 N 组中选 k 组做 test、剩余 N-k 做 train——**遍历所有 C(N,k) 种选择形成多条 backtest 路径**，每条路径施加 purged k-fold 的 purging + embargo；最终从多条路径的 Sharpe 分布推"策略 Sharpe ≥ X"的 p-value。
>
> —— López de Prado, *Advances in Financial Machine Learning* (2018), Ch. 7

**3.2 为什么需要 purged + embargo**

**问题**：金融时间序列的"标签"（label）通常是事件窗口（如"未来 5 天收益"），而非单 bar——这意味着即使 train/test 切分正确，**某些 train 样本的 label 仍包含 test 时段的未来信息**（look-ahead leakage）。

**purging 的含义**：
```
传统 K-Fold：
[TRAIN1][TRAIN2][TEST][TRAIN3][TRAIN4]

Purged K-Fold（删除 train 中与 test label 时段重叠的样本）：
[TRAIN1][TRAIN2][X][TEST][X][TRAIN4]
                                ↑ 删去与 test label 重叠的样本
```

**embargo 的含义**：在 test 段结束后，再排除一段 train 数据（避免 train 末端的样本通过自相关 / 微观结构偏差"偷看"test）：
```
Purged + Embargo K-Fold：
[TRAIN1][TRAIN2][X][TEST][EMBARGO][TRAIN4]
                                  ↑ 多排除 embargo 长度的 train 样本
```

**embargo 长度的选择**：
- 日数据：embargo = 1-5 个交易日（保守）
- 分钟数据：embargo = 1-30 分钟（依策略持仓时间）
- 高频（秒级）：embargo 至少覆盖典型持仓时间的 1x

**承自 paperswithbacktest.com + Medium 系列博文**：
> "对每日数据，embargo 可能只需几天；对高频数据，可能需要分钟级 embargo 来缓解泄漏风险。"

**3.3 CPCV 的数学结构：C(N, k) 条路径**

**核心组合公式**：
```
# 路径数 = C(N, k)
# 即从 N 组里选 k 组做 test 的组合数

C(N, k) = N! / (k! · (N − k)!)

常用配置：
- N = 6, k = 2 → C(6,2) = 15 条路径
- N = 8, k = 2 → C(8,2) = 28 条路径
- N = 16, k = 2 → C(16,2) = 120 条路径
- N = 16, k = 4 → C(16,4) = 1820 条路径（重计算）
```

**每条路径的 Sharpe 估计**：在选定 test 组上评估策略、计算 Sharpe → 总共 C(N,k) 个 Sharpe 值。

**3.4 CPCV 的 Python 工程实现**

承自 `skfolio.model_selection.CombinatorialPurgedCV` + Towards AI Medium + stats.stackexchange 代码片段：

```python
from skfolio.model_selection import CombinatorialPurgedCV
import numpy as np

# N=6 组、k=2 测试组、purged_size=1、embargo_size=1
cv = CombinatorialPurgedCV(
    n_folds=6,        # N 总组数
    n_test_folds=2,   # k 测试组数
    purged_size=1,    # purging 长度（组数）
    embargo_size=1,   # embargo 长度（组数）
)

for i, (train_index, tests) in enumerate(cv.split(X)):
    print(f"Split {i}:")
    print(f"  Train: {train_index}")
    for j, test_index in enumerate(tests):
        print(f"  Test {j}: {test_index}")
# → 输出 15 条路径（N=6, k=2）
```

**手写版**（来自 stats.stackexchange，最简版）：

```python
import numpy as np
from itertools import combinations

def cpcv_paths(N, k):
    """生成 CPCV 的所有 (train_indices, test_indices) 组合"""
    groups = list(range(N))
    paths = []
    for test_groups in combinations(groups, k):
        test = [g for g in groups if g in test_groups]
        train = [g for g in groups if g not in test_groups]
        paths.append((train, test))
    return paths

# 示例：N=6, k=2 → 15 条路径
paths = cpcv_paths(6, 2)
print(len(paths))  # 15
```

**3.5 CPCV 的 p-value 推导：核心数学**

承自 ScienceDirect 2024 论文 + AFML Ch. 12 描述：

```python
def cpcv_pvalue(path_sharpes, X=0):
    """
    从 CPCV 多重 backtest 推导"Sharpe ≥ X"的 p-value
    
    path_sharpes: list of length C(N,k)，每条 CPCV 路径的 Sharpe
    X: 阈值（通常为 0）
    """
    path_sharpes = np.array(path_sharpes)
    # 单边 p-value = "Sharpe ≥ X"的路径数 / 总路径数
    p_value = np.mean(path_sharpes >= X)
    return p_value

# 示例：15 条路径，Sharpe ≥ 0 的路径有 10 条 → p-value = 0.67
sharpes = [0.5, -0.2, 0.8, 0.1, 0.3, -0.5, 0.7, 0.2, -0.1, 0.4, 0.6, 0.0, 0.3, 0.9, -0.3]
p = cpcv_pvalue(sharpes, X=0)
print(f"p-value (Sharpe ≥ 0): {p:.2f}")  # ≈ 0.67
```

**关键统计性质**：
- 每条路径是"独立 regime 的样本"
- 多条路径的 Sharpe 分布 ≈ 策略 Sharpe 在样本外总体中的经验分布
- p-value 不是 t 检验的 p-value，但语义类似——是"在 N 组时间切分下，策略 Sharpe ≥ X 的频率"

**3.6 CPCV 的优势 vs K-Fold / Purged K-Fold / Walk-Forward**

承自 ScienceDirect 2024 "Backtest overfitting in the machine learning era" 实证论文（28 个策略配置 × 1000 次模拟）：

| 方法 | PBO（中位数，越低越好） | DSR（中位数，越高越好） | 结论 |
| --- | --- | --- | --- |
| **K-Fold** | 高 | 低 | 无 purging → 严重过拟合 |
| **Purged K-Fold** | 中高 | 中 | 修了 purging 但单路径 |
| **Walk-Forward** | **最高**（最差） | 最低 | 多重检验未修正 |
| **CPCV** | **最低**（最优） | **最高** | 多重路径 + purged + embargo 全面胜出 |

**关键发现**（论文摘要）：
> "CPCV 显著优于 K-Fold、Purged K-Fold、特别是 Walk-Forward，体现在 PBO 更低、DSR 更高。Walk-Forward 的 PBO 最高，DSR 最低。"

**为什么 Walk-Forward 反而差**：本质是多次单假设检验，无多重检验修正——每一段 OOS 都"独立"地被检验，但没有用 DSR / PBO 修正"我做了多少次这样的检验"。

**3.7 CPCV 的工程参数选择**

| 参数 | 含义 | 推荐范围 | 加密默认 |
| --- | --- | --- | --- |
| **N** | 总组数 | 5-20 | 6-10（数据有限） |
| **k** | 测试组数 | 1-N/2 | N/2（最大化路径数） |
| **purged_size** | 标签泄漏剔除长度 | 1-3 组 | 1（funding 8h 周期对账） |
| **embargo_size** | 测试后冷却长度 | 1-3 组 | 1（避免 regime 切换污染） |
| **目标函数** | Sharpe / Omega / Calmar | 依策略目标 | Sharpe（频率套利最常用） |

**N 和 k 的选择对路径数的影响**：

```

N=5        5      10     10     5      1
N=6        6      15     20     15     6
N=8        8      28     56     70     56
N=10       10     45     120    210    252

```

**实际工程推荐**：
- **快速 PoC 阶段**：N=6, k=2 → 15 条路径（5-10 分钟完成）
- **上实盘前终审**：N=10, k=3 → 120 条路径（1-2 小时完成）
- **机构级策略**：N=16, k=4 → 1820 条路径（数小时，需并行化）

**3.8 CPCV 的计算成本分析**

**单条 backtest 成本**（费率套利策略，1 年日数据）：
- 策略逻辑：~1s
- 数据加载 + 滑点建模：~1s
- 总计：~2s/路径

**C(N, k) 路径总成本**：
```
N=6, k=2:  15 × 2s   = 30s
N=10, k=3: 120 × 2s  = 4min
N=16, k=4: 1820 × 2s = 1h
N=20, k=5: 15504 × 2s = 8.6h
```

**对 100 USDT 项目的实际意义**：
- 全 N=16, k=4 跑完 ≈ 1 小时，单次运行可接受
- 但若要做参数扫描（5 参数 × 3 值 = 243 配置 × CPCV）→ 总成本 243 小时 = 不可行
- **解决**：先粗筛（in-sample PoC）→ 缩到 5-10 配置 → 跑 CPCV → 选赢家再 walk-forward 验证

**3.9 CPCV 的局限与扩展**

**局限**：
1. **数据量要求**：C(N,k) 条路径每条都要有足够数据；N=6、k=2 需要至少 6 段能完整评估策略的样本（典型 1 年日数据能切）
2. **regime 静态假设**：CPCV 假设所有路径来自同一 regime 的 iid 切分；若历史包含 regime 切换（如 2020-03 加密市场结构变化），CPCV 的"路径独立性"假设被违反
3. **算力成本**：见 §3.8——对参数空间大的策略不可行
4. **目标函数选择敏感**：用 Sharpe 算 vs 用 Omega 算，p-value 可能差很多

**扩展（承自 ScienceDirect 2024 论文）**：
- **Bagged CPCV**：在 CPCV 路径上再加 bagging（自助法聚合），进一步降低方差
- **Adaptive CPCV**：根据市场 regime 动态调整 purged_size 和 embargo_size（regime 切换频繁时放大）
- **Monte Carlo CPCV**：在 CPCV 路径上叠加蒙特卡洛模拟，对策略 Sharpe 做参数化分布估计

**3.10 CPCV vs CSCV（PBO 的实现）的区别**

| 维度 | CSCV（实现 PBO） | CPCV（实现 Sharpe 分布） |
| --- | --- | --- |
| **目标** | 估计"is-best 过拟合的概率" | 估计"策略 Sharpe 的分布 + p-value" |
| **输出** | 单一标量 PBO | 多条 Sharpe + p-value |
| **对称性** | 必须对称切分（S 组 → S/2） | 无对称要求（任意 k） |
| **典型 N** | 16（对称切分用） | 6-16 |
| **典型路径数** | C(16, 8) = 12870 | C(N, k) 灵活 |
| **关键来源** | Bailey 2014 PBO | López de Prado 2018 AFML Ch.7 |
| **配合使用** | CSCV 算 PBO → CPCV 算 Sharpe 分布 → 双重证据 | |

**实战建议**：跑 CPCV 的同时用 CSCV 算 PBO——前者回答"Sharpe 分布是什么"，后者回答"我挑出的'最佳'有多大概率是 overfit"。

### 第四章　多周期 Walk-Forward Optimization（WFO）

**4.1 WFO 的工程实现细节**

承自 SusanPotter.net / AronGroups / Vantixs / TowardsAI Medium 的工程实践：

```python
import numpy as np
import pandas as pd

def walk_forward(prices, strategy, n_is=252, n_oos=63, anchored=False):
    """
    prices: 价格序列
    strategy: 接受 prices 返回信号的 callable
    n_is: in-sample 窗口长度（日数）
    n_oos: out-of-sample 窗口长度（日数）
    anchored: True=锚定扩展窗口，False=滚动固定窗口
    """
    n = len(prices)
    step = n_oos
    start = 0 if anchored else n - n_is - n_oos
    
    oos_results = []
    while start + n_is + n_oos <= n:
        # IS 段：调参
        is_prices = prices.iloc[start:start+n_is]
        best_params = strategy.fit(is_prices)  # 内部网格搜索最优参数
        
        # OOS 段：用最优参数评估
        oos_prices = prices.iloc[start+n_is:start+n_is+n_oos]
        oos_pnl = strategy.evaluate(oos_prices, best_params)
        oos_results.append(oos_pnl)
        
        # 滚动步长
        start += step
    
    return pd.concat(oos_results)
```

**4.2 Anchored vs Rolling 的实证取舍**

| 维度 | Anchored（扩展窗口） | Rolling（固定窗口） |
| --- | --- | --- |
| **数据量** | 随步数累积 | 固定 |
| **regime 切换敏感度** | 低（旧数据拖拽） | 高（自适应最近） |
| **参数稳定性** | 高（样本量大） | 低（样本量受限） |
| **适合策略** | 长期趋势、长记忆 | 均值回归、短周期、动量 |
| **计算成本** | 高（每次重算全部历史） | 低（固定窗口） |
| **加密推荐** | 大币趋势（BTC/ETH 周级别以上） | 费率套利、短期动量 |

**Susan Potter 经验法则**（susanpotter.net）：
> "如果一个策略在 anchored 和 rolling 两种 walk-forward 配置下都通过，这是有意义的证据；只过一种，证据中等；都不过，**别上线**。"

**4.3 WFO 的关键设计参数**

| 参数 | 推荐值 | 选择依据 |
| --- | --- | --- |
| **IS 窗口长度** | ≥ 1.5 × 策略最大持仓时间 | 至少覆盖一个完整 cycle |
| **OOS 窗口长度** | ≥ 策略最大持仓时间 / 1-3 个月 | 足以做统计推断 |
| **步长** | = OOS 窗口长度 | 防止 overlap 泄漏 |
| **总步数** | ≥ 8-10 步 | 足够覆盖多个 regime |
| **参数扫描范围** | ≤ 5-8 个维度 | 避免维度灾难 |

**4.4 WFO 的"参数稳定性测试"**

WFO 不止是"看 OOS Sharpe"，还要看**每一步选出的最优参数是否稳定**：

```python
def parameter_stability(wfo_results):
    """检查每步选出的参数是否在合理范围内稳定"""
    all_params = pd.DataFrame([r['best_params'] for r in wfo_results])
    
    # 每个参数的变异系数（CV）
    cv = all_params.std() / all_params.mean()
    
    # 规则：CV > 0.5 → 参数不稳定 → 策略不可信
    unstable = cv[cv > 0.5].index.tolist()
    return unstable

# 用法
unstable_params = parameter_stability(wfo_results)
if unstable_params:
    print(f"⚠️ 不稳定参数：{unstable_params}")
    print("策略在不同 regime 选了不同最优值 → 不可信")
```

**4.5 WFO 与 CPCV 的配合**

WFO 跑完 → 看参数稳定性 + OOS Sharpe 序列 → 把 OOS Sharpe 序列作为 CPCV 的输入做二次验证：

```
WFO: 10 步 × 每步 1 OOS Sharpe → 10 个 Sharpe 值
CPCV: 把 10 个 Sharpe 视为"路径 Sharpe" → 算 p-value

如果 WFO 10 步 Sharpe 都在 ±2σ 内 → p-value 高（Sharpe 稳定）
如果其中 8 步 Sharpe > 0、2 步 < 0 → p-value 中等（可能 regime 切换）
如果其中 3 步 > 0、7 步 < 0 → p-value 低（多数 OOS 段亏损）
```

**WFO 的真正价值**：不是"看一次 OOS 好不好"，而是"看 OOS Sharpe 在多个时间窗口上的分布"。

**4.6 WFO 与 Deflated Sharpe 的修正**

WFO 的 10 个 OOS Sharpe 平均值 = 策略的真实 Sharpe 估计。
WFO 的 10 个 OOS Sharpe 标准差 = Sharpe 的稳定性指标。

**DSR 修正（承自 Bailey-López de Prado 2014）**：
- 把 WFO 视为"我做了 N 次试验"——N = WFO 步数
- 期望最大 Sharpe = √(2 ln N) × SR_std
- DSR(WFO) = "WFO 平均 Sharpe 超过 null 期望最大 Sharpe 的概率"

**实战**：WFO 10 步的平均 Sharpe 0.8、null 期望最大 Sharpe 1.2（10 次试验）→ DSR(WFO) < 0.5 → "WFO 平均 Sharpe 不显著超过 null"

### 第五章　蒙特卡洛模拟路径生成与块状 bootstrap

**5.1 为什么回测需要蒙特卡洛**

回测数字（Sharpe、回撤、年化）是**点估计**——告诉你"这一次回测的样子"。蒙特卡洛把这些点估计扩展为**分布**：
- "Sharpe 的 95% 置信区间是多少"
- "最坏情况下回撤是多少"
- "不同路径下策略的盈利概率分布"

**5.2 蒙特卡洛路径生成的四种方法**

**方法 1：iid bootstrap（不推荐用于金融）**

把历史收益序列当作 iid 样本，有放回抽样生成新路径。

**致命问题**：金融收益序列自相关极强（BTC 日收益 lag-1 自相关 0.05-0.15、绝对收益 lag-1 自相关 0.3-0.5），iid bootstrap 会：
- **低估尾部风险**（罕见但连续的大涨/大跌被随机打散）
- **抹掉波动率聚集**（GARCH 效应）
- **错误估计 Sharpe 方差**

**方法 2：块状 bootstrap（block bootstrap）**

保留时间顺序的局部块结构：
```python
def block_bootstrap(returns, block_size=21, n_sims=1000, horizon=252):
    """
    returns: 历史日收益序列
    block_size: 块长度（默认 21 = 1 个月交易日）
    n_sims: 模拟路径数
    horizon: 每条路径的长度（日）
    """
    n = len(returns)
    n_blocks = int(np.ceil(horizon / block_size))
    paths = []
    
    for _ in range(n_sims):
        path = []
        for _ in range(n_blocks):
            # 随机选起始位置，抽 block_size 长的块
            start = np.random.randint(0, n - block_size)
            path.extend(returns[start:start+block_size])
        paths.append(path[:horizon])
    return np.array(paths)
```

**优点**：保留局部自相关 + 波动率聚集
**缺点**：块边界处不连续（连续选 block 时衔接不自然）

**方法 3：Stationary bootstrap（Politis-Romano 2004）**

改进的块状 bootstrap——块长度是**几何分布**（随机），消除固定块长的人工痕迹：

```python
def stationary_bootstrap(returns, expected_block_size=21, n_sims=1000, horizon=252):
    n = len(returns)
    p = 1.0 / expected_block_size  # 块结束的几何分布参数
    paths = []
    
    for _ in range(n_sims):
        path = []
        while len(path) < horizon:
            start = np.random.randint(0, n)
            block_len = np.random.geometric(p)
            path.extend(returns[start:start+block_len])
        paths.append(path[:horizon])
    return np.array(paths)
```

**优点**：理论上更稳健（Politis-Romano 2004 给出极限定理）
**缺点**：实现稍复杂，对加密日数据经验上与块状 bootstrap 差异不大

**方法 4：GARCH-MC（动态波动率蒙特卡洛）**

用 GARCH(1,1) 拟合历史收益的动态方差，然后用拟合参数模拟新路径：

```python
from arch import arch_model

def garch_mc(returns, n_sims=1000, horizon=252):
    # 拟合 GARCH(1,1)
    am = arch_model(returns, vol='GARCH', p=1, q=1)
    res = am.fit(disp='off')
    
    # 用拟合参数模拟
    sims = res.forecast(horizon=horizon, simulations=n_sims)
    paths = sims.simulations.values[-1, :, :].T  # shape (n_sims, horizon)
    return paths
```

**优点**：完整保留波动率聚集 + 厚尾
**缺点**：依赖 GARCH 假设（不一定总是对的）

**5.3 加密场景的方法选择**

| 方法 | 自相关保留 | 波动率聚集 | 厚尾 | 计算成本 | 推荐度 |
| --- | --- | --- | --- | --- | --- |
| **iid bootstrap** | ✗ | ✗ | 部分 | 极低 | ✗（金融禁用） |
| **块状 bootstrap** | ✓ | 部分 | ✓ | 低 | ✅ 加密默认 |
| **Stationary bootstrap** | ✓ | 部分 | ✓ | 低 | ✅ 严谨场景 |
| **GARCH-MC** | ✓ | ✓ | ✓ | 中 | ✅ 加密进阶 |
| **agent-based simulation** | ✓ | ✓ | ✓ | 高 | ✗（研究用） |

**100 USDT 项目推荐**：
- 默认用**块状 bootstrap**（block_size = 策略平均持仓时间 × 2）
- 进阶场景用 GARCH-MC（需要装 arch 包）

### 第六章　加密市场回测的特殊性

**6.1 加密收益的非平稳性**

加密资产（特别是 BTC/ETH 之外的山寨币）的统计特征随时间剧烈变化：
- **波动率 regime**：2020 年 BTC 日波动 ~3%、2022-05 LUNA 期间 ~10%、2024 常态 ~4%
- **相关性 regime**：常态 BTC-ETH 0.5、危机 0.9+（承自《风险量化》§6.3）
- **资金费率 regime**：牛市 0.01-0.05% 正费率常态化、熊市 20-25% 时间为负（承自《架构初稿》§L5 阶段 1）

**对回测的含义**：
- **训练期 / 测试期的 regime 必须分开报告**——不能用 2021 牛市训练、2022 熊市测试，反之亦然
- **regime 检测 + 分 regime 跑 CPCV** 是必要的工程要求
- **不要用单一长窗口做 in-sample**——把 2018-2024 整个用作 in-sample 必然过拟合到某个特定 regime

**6.2 24/7 与"周末效应"**

加密市场 24/7 无间断，但**有效深度**（按 spread/depth 衡量）在"亚洲深夜"和"周末"显著缩水：
- UTC 02-10（亚洲深夜）BTC depth 常只剩白天 20-40%
- 周五晚-周日 BTC spread 扩大 20-50%

**对回测的含义**：
- 简单的"按日均匀抽样"会忽视周末效应
- **需要按"时间类型"分层抽样**（工作日白天 / 工作日夜间 / 周末）
- 蒙特卡洛模拟时**不要把周末当作工作日的均匀版本**

**6.3 资金费率结算窗口的微观结构跳变**

承自《市场微观结构与滑点建模》§5.5——结算前 1-2min 的 spread 跳升 10-50%。

**对回测的含义**：
- **结算时点附近的成交成本要乘 1.5-2x buffer**
- **避免在结算前后 5min 内强平**（要纳入策略规则）

**6.4 插针（wicks）与异常数据**

加密常见 5min 内 -5% 然后回弹（"插针"），多为流动性极端稀薄时段（深夜、重大新闻前）：

```python
def detect_wicks(ohlcv, threshold=0.05):
    """检测插针：5min 内 max(|high-low|)/open > threshold"""
    wick = (ohlcv['high'] - ohlcv['low']) / ohlcv['open']
    return wick > threshold
```

**对回测的含义**：
- **是否剔除插针是策略哲学选择**：插针是 alpha 来源（均值回归策略）还是噪声（应该过滤）？
- **必须明确文档化"插针处理规则"**——回测时统一

**6.5 前视偏差的多重来源**

加密场景特有的前视偏差：
1. **链上数据确认延迟**：BTC 约 10min、ETH 约 12s（承自《成功失败》§7.2）——回测假设"立即可见"即引入偏差
2. **上币/退市信息**：回测假设提前知道上架消息（如某币被 Binance 上下架）
3. **收盘订单簿深度**：用收盘时点的 order book 评估日内滑点——实际上日内 order book 在 1 秒级别跳变
4. **Funding rate 历史快照**：freqtrade 等只能拿到 8h 结算的历史快照，拿不到分钟级实时预测费率（承自《架构初稿》P0-3）
5. **交易所下线币种**：被下架的币种历史数据不完整，回测时不能"假装它一直在"

**对回测的含义**：
- 必须严格使用**真实可见时刻的数据**
- 数据可用性审计清单（参见 §7.5）是 CPCV/WFO 前的强制门槛

**6.6 加密场景的"未来函数清单"**

承自《自动量化加密货币的成功与失败》§3.4 + §7.2 + §9.6 + 本条累积：

| 未来函数来源 | 检测方法 | 修复 |
| --- | --- | --- |
| **用未来 funding 成交** | 看成交时点 vs funding 结算时点 | 仅用过去已结算 funding |
| **用未来 order book** | 用 L3 diff 流 replay 检查 | 用 L2 快照 + 时间戳 |
| **用未来上币信息** | 上下架日期审计 | 时间截断到上架前 |
| **用插针后的 close** | 检查 fill 假设 | 强制"按时间戳前最近价"成交 |
| **用未确认的链上数据** | 用 confirmation depth ≥ N | 设置深度门槛 |
| **用未发生的 funding 反转** | 看结算日志 | 用真实历史结算序列 |
| **用未来的 funding 预测** | 检查是否用预测而非结算 | 强制只用历史结算费率 |

```python
def purged_k_fold_audit(returns, labels, n_splits=5, embargo_pct=0.01):
    """
    用 purged k-fold 检查标签泄漏
    returns: 特征矩阵（每行一个时间点）
    labels: 标签（每行对应未来 8h funding）
    """
    from sklearn.model_selection import KFold
    kf = KFold(n_splits=n_splits, shuffle=False)  # 时间顺序
    
    embargo_size = int(len(returns) * embargo_pct)
    leakage_count = 0
    
    for train_idx, test_idx in kf.split(returns):
        # 检查 train 末端与 test 起端的 label 重叠
        train_end = train_idx[-1]
        test_start = test_idx[0]
        
        # 假设 label 窗口 = 8h = 1 个 funding 周期
        if test_start - train_end < embargo_size:
            leakage_count += 1
    
    return {
        'leakage_count': leakage_count,
        'pass': leakage_count == 0,
        'recommendation': 'PASS' if leakage_count == 0 else '需要增大 embargo'
    }
```

**通过标准**：leakage_count = 0 且所有 checks 全 True。

**第 2 关：CPCV 多重 backtest + PBO/DSR**

```python
def phase1_cpcv_pipeline(funding_history, params_grid, N=6, k=2):
    """
    Phase 1 费率套利的 CPCV 流水线
    
    funding_history: 资金费率历史序列
    params_grid: 参数网格（开仓阈值、目标区间、退出条件等）
    """
    # Step 1: 全网格 in-sample PoC（粗筛）
    is_sharpes = {}
    for params in params_grid:
        pnl = simulate_strategy(funding_history, params, mode='in_sample')
        is_sharpes[params] = sharpe(pnl)
    
    # Step 2: 选 top 10% 配置跑 CPCV
    top_params = sorted(is_sharpes.items(), key=lambda x: -x[1])[:max(1, len(params_grid)//10)]
    
    # Step 3: CPCV 多重 backtest
    cpcv_sharpes = {}
    for params, _ in top_params:
        # N=6, k=2 → 15 条路径
        sharpes_per_path = []
        for train_idx, test_idx in cpcv_paths(N, k):
            pnl_test = simulate_strategy(
                funding_history.iloc[test_idx], params, mode='out_of_sample'
            )
            sharpes_per_path.append(sharpe(pnl_test))
        cpcv_sharpes[params] = sharpes_per_path
    
    # Step 4: 算 PBO（CSCV 方法）
    all_cpcv_returns = pd.DataFrame(cpcv_sharpes)
    pbo = compute_cscv_pbo(all_cpcv_returns)
    
    # Step 5: 算 DSR
    best_sr = max(s.mean() for s in cpcv_sharpes.values())
    n_trials = len(params_grid)
    t_obs = len(funding_history)
    dsr = deflated_sharpe_ratio(best_sr, expected_max_sr(n_trials), t_obs)
    
    return {
        'pbo': pbo,
        'dsr': dsr,
        'top_params_sharpes': cpcv_sharpes,
        'gate': 'PASS' if (pbo < 0.3 and dsr > 0.95) else 'FAIL'
    }
```

**通过标准**：
- PBO < 0.3（"is-best 过拟合"概率 < 30%）
- DSR > 0.95（"最佳 Sharpe 超过 null"概率 > 95%）
- 15 条 CPCV 路径的 Sharpe 分布：均值 > 0、最坏 > -0.5

**7.6 工程落地的代码 sketch**

```python
# 完整流水线伪代码
def phase1_full_backtest_pipeline(funding_history, market_data, params_grid):
    """
    Phase 1 完整回测流水线（5 关）
    """
    results = {}
    
    # 关 1：未来函数审计
    audit = future_function_audit(funding_history, market_data)
    results['gate1'] = audit
    if not audit['pass']:
        return results  # FAIL → 终止
    
    # 关 2：CPCV
    cpcv = phase1_cpcv_pipeline(funding_history, params_grid, N=6, k=2)
    results['gate2'] = cpcv
    if cpcv['gate'] == 'FAIL':
        return results
    
    # 关 3：多周期 WFO
    wfo = multi_horizon_wfo(funding_history, cpcv['best_params'])
    results['gate3'] = wfo
    if not all_pass_wfo(wfo):
        return results
    
    # 关 4：MC 压力测试
    mc = mc_stress_test(funding_history, cpcv['best_params'])
    results['gate4'] = mc
    if mc['loss_prob'] > 0.3 or mc['p5_pnl'] < -5:
        return results
    
    # 关 5：加密 RST
    rst = crypto_rst(market_data['historical_pnl'], cpcv['best_params'])
    results['gate5'] = rst
    if rst['gate'] == 'FAIL':
        return results
    
    # 5 关全绿
    results['final_verdict'] = 'PASS - 准许 paper trading'
    results['best_params'] = cpcv['best_params']
    return results
```

**7.7 关键观察：CPCV 在 100 USDT 体量下的实际算力开销**

**算力清单**（在 100 USDT 项目语境下）：
- 数据规模：2 年 funding 历史 ≈ 730 个日点（每点 3 个 8h 结算）= 2,190 个 funding 记录
- CPCV(N=6, k=2)：15 条路径 × 1s/路径 ≈ 15s
- 1000 次 MC 模拟：1000 × 1s ≈ 17min（单线程）
- 多周期 WFO × 5 个 horizon：5 × 2min ≈ 10min
- **总计：单次完整上强度评估 ≈ 30min**

**vs 实盘亏损成本**：
- 30min 计算 vs 一次 20 USDT 回撤 = 1 USDT/min 价值的"省钱保险"
- **算力完全不是瓶颈**——本质上是"愿不愿意在动手前多想 30min"

**对比研究**：ScienceDirect 2024 论文在 1000 次模拟上跑 28 个策略 × 4 种 CV 方法（CPCV/KFold/Purged/WF）→ 总耗时数小时、单策略单方法 ≈ 数秒——和本项目的估算一致。

**7.8 Archegos/3AC 案例的事后 CPCV 复盘（思想实验）**

**Archegos（2021.03 爆仓，世纪爆仓）**：
- 持仓：5x 杠杆的 ViacomCBS、Discovery、百度、腾讯音乐等
- 集中度：单一券商（Prime Broker）持仓占比 > 50%
- 触发：ViacomCBS 增发价低于市场价 → 5x 杠杆被强平 → 连锁爆仓

**事后用 CPCV 复盘能否抓到早期信号**：
- 把 Archegos 的持仓组合（ViacomCBS、Discovery 等）做成"伪策略"
- 把 2020-01 到 2021-03 的日数据切成 N=10, k=3（120 条 CPCV 路径）
- 每条路径评估"组合的最大回撤"
- **预期结果**：120 条路径里约 80-100 条会显示"组合在 30% 集中度下回撤 > 30%" → PBO 显示"该组合的'盈利'来自集中度而非 alpha" → **CPCV 能在 2020 年中就抓到信号**

**3AC（2022.07 破产）**：
- 持仓：GBTC 套利 + stETH + 多个 Alt 杠杆
- 杠杆：20x
- 触发：GBTC 折价反转 + stETH 脱锚

**事后用 CPCV 复盘**：
- 把 GBTC 套利头寸作为"伪策略"，用 GBTC 历史价差 + funding 费率数据跑 CPCV
- N=8, k=2 → 28 条路径
- **预期结果**：当 GBTC 价差从溢价 20% 跌到折价 5% 时，几乎所有路径都显示"该套利的预期收益转负" → CPCV 能抓到，但 3AC 的真实问题不是 CPCV 能解决的——而是 **杠杆（20x）+ 隐瞒敞口（贷方不知真实规模）**——这部分不是回测方法论问题，是对手方信息披露问题

**结论**：CPCV 能抓"策略本身的过拟合"，**抓不到"杠杆倍数过高 + 对手方隐瞒"**——这两个需要分立的风控层。

**7.9 100 USDT 项目用 CPCV 的具体配置建议**

| 项 | 建议值 | 理由 |
| --- | --- | --- |
| **N（总组数）** | 6-8 | 数据有限（~2 年），太细的切分每组样本量不足 |
| **k（测试组数）** | N/2 = 3-4 | 最大化路径数 |
| **路径数** | 20-70 | 足够估计 p-value，但单次跑 < 5min |
| **purged_size** | 1（funding 周期 8h） | 与策略标签周期对齐 |
| **embargo_size** | 1-2（funding 周期 8h-16h） | 防止相邻组通过 funding 序列关联 |
| **目标函数** | Sharpe | 频率套利的标准选择 |
| **DSR 的 N_trials** | 参数网格的总组合数 | 不能少报——少报会让 DSR 假阳性 |

**工程命令**（伪代码）：

# 4. 算 DSR（用 in-sample 网格扫描数作为 N_trials）
n_trials = len(params_grid)  # 例如 100
best_sr = max(sharpes_per_path)
