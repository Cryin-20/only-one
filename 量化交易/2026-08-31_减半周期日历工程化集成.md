## 可复用原则（决策时引用）

1. **日历规律还在，指标 trigger 已哑火**：2024-04 减半后第 534 天（2025-10-09）BTC 仍按历史 ±534 天节奏到达 $124,824 ATH——但 Pi Cycle Top 完全没触发、MVRV 仅 2.29（历史顶部 2.93-5.91）、Puell < 4.0、Mayer < 2.4。"日历"是结构性 supply shock 节奏，"指标"是被 ETF + 机构化结构性平移后的反应函数。**减半日历可作为 regime 的"时间协变量"（time-varying transition probabilities，承自外脑 #14 §4.4 Filardo 1994），不能作为单点触发器**。

2. **顶部警戒用多指标叠加，不用单指标**：MVRV > 3.0 + Puell > 3.5 + NuPL > 0.65 + Pi Cycle 接近触发 = 多指标叠加触发顶部警戒 mode。任一指标独立触发 = 弱信号（30-50% 概率）；四指标叠加 = 强信号（>80%）。承自外脑 #18 §7.5 + §10.3。**2025-10 顶部特殊性警示**：四指标集体失声，单指标 + 双指标叠加可能仍为弱信号，必须加 ETF flow + 宏观 5 维度交叉。

3. **Cycle Flattening = 4 年节奏还在 + 峰值期延长 + 回撤幅度递减**：crypto.news 2026 + arxiv 2607.26188 (2026) 三方验证——回撤幅度逐次递减 -84% / -77% / -51%，ETF 月度资金流量 > 矿工年产出一个数量级，结构性底部上移 institutional floor ≈ $80k。**顶部判断从"单点突破"转为"指标叠加 + 时间窗口"**——不能再用"减半 + 12-18 月精确日"预测顶部。

4. **减半前后 6 月 = 费率套利的"窗口期"**：减半前 6 月矿工抛压增大（卖币买矿机/付电费）→ funding rate 短期走高；减半后 1-3 月矿工收入降 → funding 短暂转负（参考 2020-05 减半后 2020-08 费率短暂为负）；减半后 6-12 月 = funding 回升甜蜜区。承自外脑 #18 §5.4 + #1 §7。**这是项目费率套利的"日历机会"**。

5. **顶部警戒 mode 收紧熔断 + 缩小仓位 + 提高空腿保证金缓冲**：当 4 指标叠加触发顶部警戒 mode（外脑 #18 §10.3 + #12.2）——日亏熔断从 -2% 收紧到 -1%，仓位上限从 80% 收紧到 50%，空腿保证金缓冲从 30% 提高到 50%，复盘频率从周度提升到日度，飞书推送频次提升到每 4 小时一次。**顶部警戒是"动态熔断线"，不是"停机信号"**。

6. **Phase 1 不看减半日历，Phase 3 才集成**：费率套利 delta 中性、不依赖方向判断——减半日历对 Phase 1 P&L 没有直接影响（承自外脑 #18 §10.1）。**Phase 3 把"减半日历 + 顶部警戒 mode + 持币 Long Put"作为反脆弱组合工程实现**——这是项目从"工程验证"到"长期可投资"的升级路径，承自外脑 #17 §10.3。

7. **期权对冲集成 = 持币 + Long Put 反脆弱组合**：Phase 3 集成 Deribit / IBIT 期权，月度买 30 天 OTM Put 成本约 1-3% 名义本金（100 USDT 折算 1-3 USDT/月），保护效果 = BTC 跌到 OTM Put 行权价时本金有保险。承自外脑 #17 §12。**Long Put 是给组合买的"保险"——短期亏权利金，长期不被尾部归零**。

8. **诚实声明 = 哪些是已发生数据 / 哪些是预测 / 哪些是机制推断**：
   - **已发生**：4 次减半日（2012-11-28 / 2016-07-09 / 2020-05-11 / 2024-04-20）+ 4 次顶部日（2013-12 / 2017-12-17 / 2021-11-10 / 2025-10-09）+ 链上指标历史值（外脑 #18 §6-§7 详列）
   - **机制推断**：减半后 12-18 月顶部经验规律（n=4 统计推断薄弱，背后供应减半经济学理由真实）
   - **预测**：2028-03 减半倒计时 + 顶部窗口（2028-Q3 - 2029-Q2）+ 顶部警戒 mode 触发（概率性，非确定性）

## 核心逻辑链

1. **前提（来自外脑 #18）**：加密市场不是"随机游走"——4 大叙事周期（减半 / ETF / 监管 / 技术）+ 链上指标（MVRV / SOPR / NUPL / Puell / Pi Cycle / LTH-STH / Exchange Netflow / Mayer Multiple / S2F）双重驱动。**叙事决定方向，指标决定幅度，但 2025-10 后指标哑火，叙事主导**。

2. **机制（减半 → 供应冲击 → 需求不变 → 价格压力上升）**：比特币每 210,000 区块（约 4 年）奖励减半——4 次减半 + 4 次"减半后 12-18 月顶部"经验规律（n=4 统计推断薄弱，但供应经济学理由真实）。2024-04-20 第 4 次减半，2028-03 预计第 5 次减半（距今约 19 个月）。

3. **机制（Cycle Flattening = 4 年节奏还在 + 峰值期延长 + 回撤幅度递减）**：2024-01-10 现货 ETF 通过 + 2024-04-20 减半的双重事件是历史上第一次。ETF 月度资金流量 > 矿工年产出一个数量级——ETF "买什么都涨 / 卖什么都跌"，把减半的"供应冲击"叙事边缘化。**顶部从"减半 + 12-18 月单点突破"转为"减半 + 12-18 月窗口 + 4 指标叠加触发"**。

4. **机制（顶部警戒 mode = 多指标叠加 + 收紧熔断 + 缩小仓位 + 期权对冲）**：当 4 指标同时进入红色区 → 进入顶部警戒 mode → 收紧熔断线 + 缩小仓位 + 提高保证金缓冲 + 复盘频率提升 + 飞书推送频次提升。这是 ES 反向校准（外脑 #3 §7）+ regime-dependent 动态熔断（外脑 #14 §11）的具体实现。

5. **机制（Phase 3 反脆弱组合 = 持币 + Long Put = Taleb 推荐）**：长期持币 + 月度买 30 天 OTM Put = 下行封顶 + 上行无顶 = 凸性组合。每月成本 1-3% 名义本金——"小额保护下行的反脆弱成本"。承自外脑 #17 §12.2。

6. **结果（项目应用）**：100 USDT 项目的费率套利**不依赖减半日历**（Phase 1），但**减半前后 6 月是费率套利的窗口期**（Phase 1 优化）；**Phase 3 把减半日历 + 顶部警戒 mode + 持币 Long Put**作为反脆弱组合工程实现——这是项目从"工程验证"到"长期可投资"的升级路径。

7. **决策口诀**：减半日历 = regime 时间协变量（Filardo 1994）；顶部警戒 = 4 指标叠加触发（不用单指标）；减半前后 6 月 = 费率窗口期（前 6 月观察 / 中 6 月风险 / 后 6 月机会）；反脆弱组合 = 持币 + Long Put + 顶部警戒 mode 三件套。

    except Exception as e:
        print(f"[ERROR] blockchain.info failed: {e}")
        # 降级到 mempool.space
        try:
            resp = requests.get("https://mempool.space/api/blocks/tip/height", timeout=10)
            resp.raise_for_status()
            return int(resp.text.strip())
        except Exception as e2:
            print(f"[ERROR] mempool.space failed: {e2}")
            return None

def fetch_network_hashrate():
    """获取网络算力（EH/s）"""
    try:
        resp = requests.get("https://mempool.space/api/v1/mining/hashrate/3d", timeout=10)
        resp.raise_for_status()
        data = resp.json()
        # current_hashrate 单位是 H/s，转换为 EH/s
        return data["currentHashrate"] / 1e18
    except Exception:
        return None

def estimate_days_remaining(blocks_remaining, avg_block_time=AVG_BLOCK_TIME_SECONDS):
    """估算剩余天数"""
    seconds = blocks_remaining * avg_block_time
    return seconds / 86400

def main():
    current_height = fetch_block_height()
    if current_height is None:
        print("[FATAL] 无法获取当前区块高度")
        return

    blocks_remaining = NEXT_HALVING_HEIGHT - current_height
    days_remaining = estimate_days_remaining(blocks_remaining)
    estimated_date = datetime.datetime.utcnow() + datetime.timedelta(days=days_remaining)
    hashrate = fetch_network_hashrate()

#### 2.1 顶部警戒 mode 触发条件（多指标叠加原则）

承自外脑 #18 §10.3 + §12.2 + §7.5：

- MVRV > 3.0 **AND** Puell > 3.5 **AND** NuPL > 0.65 **AND** Pi Cycle 接近触发（111d MA 在 350d MA × 2 ± 5% 内）
- **OR** Pi Cycle 触发（111d MA 上穿 350d MA × 2）

**中等顶部信号（概率 50-60%，2025-10 案例）**：
- MVRV > 2.5 **AND** NuPL > 0.55
- **OR** MVRV > 2.0 **AND** ETF 单日净流入 > $1B

**单一指标触发（弱信号，30-50%）**：
- MVRV > 3.5（仅 MVRV）
- NuPL > 0.75（仅 NuPL）
- Pi Cycle 触发（仅 Pi Cycle）

**2025-10 顶部特殊性**（外脑 #18 §5.2 警示）：所有经典指标集体失声——必须加 ETF flow + 宏观 5 维度交叉判断：
- ETF 单日净流入 > $1B **AND** BTC 单日涨幅 > 5% **AND** Mayer Multiple > 2.0
- **OR** 4 指标叠加 + BTC 单日突破历史新高

check_top_warning.py

ALERT_THRESHOLDS = {

def fetch_mvrv():
    """从 CoinMetrics 社区 API 获取 MVRV"""
    try:
        url = "https://community-api.coinmetrics.io/v4/timeseries/asset-metrics"
        params = {
            "assets": "btc",
            "metrics": "CapMVRVCur",
            "frequency": "1d",
            "limit_per_asset": 1,
        }
        resp = requests.get(url, params=params, timeout=15)

        return None

    """从 Glassnode 社区获取 NuPL（备选：CoinMetrics MVRV 反推）"""
    # NuPL = (Market Cap - Realized Cap) / Market Cap = 1 - 1/MVRV
    mvrv = fetch_mvrv()
    if mvrv and mvrv > 0:
        return 1 - 1/mvrv
    return None

def fetch_pi_cycle_proximity():
    """自算 Pi Cycle 接近触发度：111d MA / (350d MA × 2)"""
    try:
        # 从 CoinGecko 获取 400 天 BTC 历史价格
        url = "https://api.coingecko.com/api/v3/coins/bitcoin/market_chart"
        params = {"vs_currency": "usd", "days": 400, "interval": "daily"}
        resp = requests.get(url, params=params, timeout=15)
        resp.raise_for_status()
        prices = [p[1] for p in resp.json()["prices"]]
        
        if len(prices) < 350:
            return None
        
        ma_111 = np.mean(prices[-111:])
        ma_350 = np.mean(prices[-350:])
        pi_line = ma_350 * 2
        ratio = ma_111 / pi_line  # 1.0 = 触发
        
        # proximity = 1 - |ratio - 1|，越接近 1 表示越接近触发
        proximity = 1 - abs(ratio - 1)
        return {
            "ma_111": ma_111,
            "ma_350": ma_350,
            "pi_line": pi_line,
            "ratio": ratio,
            "proximity": proximity,
            "triggered": ratio >= 1.0
        }
    except Exception as e:
        print(f"[WARN] Pi Cycle fetch failed: {e}")
        return None

    if btc:

    triggered_strong = False

    triggers = []
    
    if mvrv and puell and nupl and pi_cycle:

**顶部警戒 mode 触发逻辑**：
- **3 维度强信号 + 1 维度中信号** → 强触发
- **2 维度强信号 + 2 维度中信号** → 中等触发
- **任一维度强信号 + 任一其他维度中信号** → 预警（准备）
- **全部中信号或弱信号** → 不触发

#### 5.2 Long Put 参数选择（基于 OTM% 和 IV）

承自外脑 #17 §5.5 + #10.3 + FalconX 2025 + Deribit statistics：

```python
#!/usr/bin/env python3
"""
long_put_selector.py
根据 BTC 价位 + 30d ATM IV + 风险预算选择最优 OTM Put
"""
import numpy as np
from scipy.stats import norm

def bs_put(S, K, T, r, sigma):
    """Black-Scholes Put 定价"""
    d1 = (np.log(S / K) + (r + 0.5 * sigma**2) * T) / (sigma * np.sqrt(T))
    d2 = d1 - sigma * np.sqrt(T)
    return K * np.exp(-r * T) * norm.cdf(-d2) - S * norm.cdf(-d1)

def select_long_put(btc_price, monthly_budget_usd, target_protection_pct=0.85, iv_atm_30d=0.50):
    """
    选择最优 OTM Put
    btc_price: BTC 当前价
    monthly_budget_usd: 月度权利金预算
    target_protection_pct: 目标保护比例（如 0.85 = BTC 跌 15% 时保险激活）
    iv_atm_30d: 30d ATM IV（年化）
    
    返回: 最优 OTM Put 配置
    """
    # 目标行权价（保护 BTC 跌到 X 时激活）
    target_K = btc_price * target_protection_pct
    
    # 30 天到期（外脑 #17 §10.3 推荐）
    T = 30 / 365
    r = 0.04  # 4% 无风险利率（美元短期国债）
    
    # 网格搜索 OTM%
    results = []
    for otm_pct in [0.05, 0.10, 0.15, 0.20, 0.25]:
        K = btc_price * (1 - otm_pct)
        sigma = iv_atm_30d * 1.05  # OTM Put IV 通常比 ATM 高 5%
        put_price = bs_put(btc_price, K, T, r, sigma)
        
        # 名义本金（按 BTC 数量）
        notional = 0.01  # 0.01 BTC = ~$1,000 名义本金（参考 Deribit 合约面值）
        cost_per_contract = put_price * notional
        contracts = monthly_budget_usd / cost_per_contract
        max_loss = btc_price - K  # 最大下行损失（行权价差）
        breakeven_drop_pct = otm_pct + (put_price / btc_price)  # 盈亏平衡所需跌幅
        
        results.append({
            "otm_pct": otm_pct,
            "K": K,
            "put_price_per_btc": put_price,
            "cost_per_contract_usd": cost_per_contract,
            "contracts": contracts,
            "max_loss_per_btc": max_loss,
            "breakeven_drop_pct": breakeven_drop_pct,
            "protection_activated_at": btc_price * (1 - otm_pct - put_price/btc_price)
        })
    
    # 推荐 10-15% OTM（外脑 #17 §10.3 推荐起点）
    return results

# 示例：BTC = $100,000，月度预算 2 USDT，30d ATM IV = 50%
results = select_long_put(100000, 2.0, target_protection_pct=0.85, iv_atm_30d=0.50)
for r in results:
    print(f"OTM {r['otm_pct']*100:.0f}%: K=${r['K']:.0f}, 权利金 ${r['put_price_per_btc']:.2f}/BTC, 成本/合约 ${r['cost_per_contract_usd']:.2f}, 合约数 {r['contracts']:.2f}, 保护激活点 ${r['protection_activated_at']:.0f}")
```

| --- | --- | --- | --- | --- | --- |
| 5% | $95,000 | $2,450 | $24.50 | 0.082 | $97,550 |

#### 5.3 持币 + Long Put 反脆弱组合的实现

承自外脑 #17 §12 + Taleb《Antifragile》：

```python
#!/usr/bin/env python3
"""
protective_put_hedge.py
月度自动买 30d OTM Put + 持币组合管理
"""
import datetime
import ccxt  # 公开交易所统一 API
import numpy as np

def setup_protective_put(
    spot_position_btc,         # 持币数量（如 0.001 BTC = $100）
    monthly_budget_usd,        # 月度权利金预算
    otm_pct,                   # OTM 百分比（如 0.10 = 10%）
    expiry_days,               # 到期天数（如 30）
):
    """
    建立持币 + Long Put 反脆弱组合
    """
    # 1. 获取当前 BTC 价格
    exchange = ccxt.deribit()  # 或 ccxt.binance() / ccxt.bybit()
    btc_price = exchange.fetch_ticker("BTC/USDT")["last"]
    
    # 2. 计算行权价（OTM Put）
    K = btc_price * (1 - otm_pct)
    
    # 3. 选择到期日（最近的 30 天后到期日）
    expiry_date = datetime.date.today() + datetime.timedelta(days=expiry_days)
    
    # 4. 下单买 Put（Deribit 限价单，按 ask 价）
    symbol = f"BTC-{expiry_date.strftime('%d%b%y').upper()}-{int(K)}-P"
    orderbook = exchange.fetch_order_book(symbol)
    ask_price = orderbook["asks"][0][0]
    
    # 5. 计算合约数（按月度预算）
    contract_size = 0.01  # Deribit BTC 期权合约面值 = 0.01 BTC
    cost_per_contract = ask_price * contract_size
    num_contracts = monthly_budget_usd / cost_per_contract
    
    # 6. 下单（限价单，按 ask 价）
    order = exchange.create_order(
        symbol=symbol,
        type="limit",
        side="buy",
        amount=num_contracts,
        price=ask_price,
    )
    
    return {
        "order_id": order["id"],
        "symbol": symbol,
        "K": K,
        "cost_usd": num_contracts * cost_per_contract,
        "num_contracts": num_contracts,
        "expiry_date": expiry_date.isoformat(),
        "spot_position_btc": spot_position_btc,
        "protection_activated_at": btc_price - (cost_per_contract / num_contracts),
    }

def roll_over_protective_put(current_put_position, days_to_expiry=3):
    """
    滚动 Long Put（到期前 3 天平仓 + 买新 Put）
    """
    if days_to_expiry > 3:
        return None
    
    # 1. 平仓当前 Put
    exchange = ccxt.deribit()
    exchange.create_order(
        symbol=current_put_position["symbol"],
        type="market",
        side="sell",
        amount=current_put_position["num_contracts"],
    )
    
    # 2. 买新 Put（同 OTM% + 新到期日）
    return setup_protective_put(
        spot_position_btc=current_put_position["spot_position_btc"],
        monthly_budget_usd=current_put_position["monthly_budget_usd"],
        otm_pct=0.10,  # 保持 10% OTM
        expiry_days=30,
    )
```

#### 5.4 反脆弱组合的 P&L 模拟

承自外脑 #17 §12.1 凸性对比：

```python
def simulate_payoff_comparison(btc_spot_path, otm_put_params, monthly_put_cost):
    """
    对比 3 种组合的 P&L：
    1. 纯持币（HODL）
    2. 持币 + Long Put（Protective Put）
    3. 纯费率套利（同所做 funding_arb，假设 delta 中性）
    """
    initial_spot = btc_spot_path[0]
    K = otm_put_params["K"]
    put_price_initial = otm_put_params["put_price"]
    
    results = []
    cumulative_put_cost = 0
    for i, spot in enumerate(btc_spot_path):
        cumulative_put_cost += monthly_put_cost
        
        # 1. 纯持币
        pnl_hodl = (spot - initial_spot) / initial_spot
        
        # 2. 持币 + Long Put（假设 Put 在到期时按内含价值结算）
        if spot < K:
            pnl_protective_put = (spot - initial_spot) / initial_spot + (K - spot) / initial_spot - cumulative_put_cost / initial_spot
            # 等于 max(spot, K) - initial_spot - 累计 put 成本
        else:
            pnl_protective_put = (spot - initial_spot) / initial_spot - cumulative_put_cost / initial_spot
            # 等于 (spot - initial_spot) - 累计 put 成本
        
        # 3. 纯费率套利（假设 delta 中性 + 累计 funding 收益）
        # 简化：funding_arb P&L ≈ funding_rate × notional × time - 滑点 - ADL 风险
        funding_pnl = 0.001 * i  # 假设每天 funding 收益 0.001（10 bps） × i 天
        pnl_funding_arb = funding_pnl - 0.0001 * i  # 减去滑点
        
        results.append({
            "spot": spot,
            "pnl_hodl_pct": pnl_hodl,
            "pnl_protective_put_pct": pnl_protective_put,
            "pnl_funding_arb_pct": pnl_funding_arb,
        })
    
    return results

# 模拟 BTC 价格路径：先涨 50%，后跌 30%
np.random.seed(42)
btc_path = [100000]
for _ in range(180):
    btc_path.append(btc_path[-1] * (1 + np.random.normal(0.001, 0.02)))
# 假设 180 天后跌到 $80,000
btc_path[-1] = 80000

results = simulate_payoff_comparison(
    btc_path,
    otm_put_params={"K": 90000, "put_price": 1500},
    monthly_put_cost=2  # 2 USDT/月
)

# 输出最终 P&L
final = results[-1]
print(f"180 天后 BTC = ${final['spot']:.0f}")
print(f"纯持币 P&L: {final['pnl_hodl_pct']*100:.2f}%")
print(f"持币 + Long Put P&L: {final['pnl_protective_put_pct']*100:.2f}%")
print(f"纯费率套利 P&L: {final['pnl_funding_arb_pct']*100:.2f}%")
```

**典型输出**：
- 纯持币：BTC 跌 20% → P&L -20%（无限下行）
- 持币 + Long Put：BTC 跌 20%（但仍在 OTM Put 行权价下方）→ P&L 约 -5%（下行封顶 + put 成本）
- 纯费率套利：delta 中性 → P&L ≈ +0.5%（funding 累计 - 滑点）

**反脆弱组合的核心优势**：下行封顶（凸性），上行无顶（持币）——BTC 涨时跟涨（扣除 put 成本），BTC 跌时损失封顶。

#### 7.3 综合数据采集 Python 脚本（每日 cron）

```python
#!/usr/bin/env python3
"""
update_onchain_metrics.py
每日采集 onchain_metrics 表的所有指标（cron: 0 7 * * * UTC = 北京时间 15:00）
"""
import json
import sqlite3
import requests
import datetime
import numpy as np
from pathlib import Path

DB_PATH = "/home/ubuntu/quant-bot/data/halving.db"

# CoinMetrics 社区 API（无 key）
COINMETRICS_API = "https://community-api.coinmetrics.io/v4"

# Glassnode 社区 API（需要 key，但有免费层）
GLASSNODE_API_KEY = "YOUR_GLASSNODE_API_KEY"  # 从 config/glassnode.env 读取

# Coinglass API（需要 key）
COINGLASS_API_KEY = "YOUR_COINGLASS_API_KEY"

def fetch_coinmetrics(metric, days=1):
    """从 CoinMetrics 社区 API 获取指标"""
    try:
        url = f"{COINMETRICS_API}/timeseries/asset-metrics"
        params = {
            "assets": "btc",
            "metrics": metric,
            "frequency": "1d",
            "limit_per_asset": days,
        }
        resp = requests.get(url, params=params, timeout=15)
        resp.raise_for_status()
        data = resp.json()
        if data.get("data"):
            return data["data"][-1]["metrics"][metric]
        return None
    except Exception as e:
        print(f"[WARN] CoinMetrics {metric} fetch failed: {e}")
        return None

def fetch_coinglass(endpoint):
    """从 Coinglass API 获取数据"""
    try:
        url = f"https://api.coinglass.com/v1/{endpoint}"
        headers = {"coinglassSecret": COINGLASS_API_KEY}
        resp = requests.get(url, headers=headers, timeout=15)
        resp.raise_for_status()
        return resp.json()["data"]
    except Exception as e:
        print(f"[WARN] Coinglass {endpoint} fetch failed: {e}")
        return None

def fetch_pi_cycle():
    """自算 Pi Cycle Top"""
    try:
        url = "https://api.coingecko.com/api/v3/coins/bitcoin/market_chart"
        params = {"vs_currency": "usd", "days": 400, "interval": "daily"}
        resp = requests.get(url, params=params, timeout=15)
        resp.raise_for_status()
        prices = [p[1] for p in resp.json()["prices"]]
        
        if len(prices) < 350:
            return None
        
        ma_111 = np.mean(prices[-111:])
        ma_350 = np.mean(prices[-350:])
        pi_line = ma_350 * 2
        ratio = ma_111 / pi_line
        proximity = 1 - abs(ratio - 1)
        
        return {
            "ma_111": ma_111,
            "ma_350": ma_350,
            "pi_line": pi_line,
            "ratio": ratio,
            "proximity": proximity,
            "triggered": int(ratio >= 1.0)
        }
    except Exception as e:
        print(f"[WARN] Pi Cycle fetch failed: {e}")
        return None

def fetch_btc_etf_daily_flow():
    """从 Coinglass 获取 BTC ETF 单日净流入"""
    try:
        data = fetch_coinglass("fundflow/etf?symbol=BTC")
        if data:
            return data[-1]["net_flow"]
        return None
    except Exception as e:
        print(f"[WARN] BTC ETF flow fetch failed: {e}")
        return None

def fetch_dvol():
    """从 Deribit 获取 BTC DVOL"""
    try:
        url = "https://www.deribit.com/api/v2/public/get_volatility_index_data"
        params = {"currency": "BTC", "timestamp": int(datetime.datetime.utcnow().timestamp() * 1000)}
        resp = requests.get(url, params=params, timeout=15)
        resp.raise_for_status()
        data = resp.json()["result"]["data"]
        for entry in data[::-1]:
            if entry[1] is not None:
                return entry[1] / 100  # Deribit DVOL 是百分位（如 50 表示 50%）
        return None
    except Exception as e:
        print(f"[WARN] DVOL fetch failed: {e}")
        return None

def update_onchain_metrics():
    """采集并写入 onchain_metrics 表"""
    today = datetime.date.today().isoformat()
    
    # 1. CoinMetrics（免费层）
    mvrv = fetch_coinmetrics("CapMVRVCur")
    nupl_from_mvrv = 1 - 1/mvrv if mvrv and mvrv > 0 else None
    
    # 2. Glassnode（如果有 API key）
    # nupl = fetch_glassnode("network/net_unrealized_profit_loss")
    # puell = fetch_glassnode("mining/puell_multiple")
    
    # 3. Coinglass
    puell_from_cg = None
    try:
        data = fetch_coinglass("index/puell")
        if data:
            puell_from_cg = data[-1]["puell"]
    except Exception:
        pass
    
    # 4. Pi Cycle（自算）
    pi_cycle = fetch_pi_cycle()
    
    # 5. ETF Flow
    etf_flow = fetch_btc_etf_daily_flow()
    
    # 6. DVOL
    dvol = fetch_dvol()
    
    # 7. BTC 价格 + Mayer
    btc_price = None
    mayer = None
    try:
        url = "https://api.coingecko.com/api/v3/coins/bitcoin/market_chart"
        params = {"vs_currency": "usd", "days": 220, "interval": "daily"}
        resp = requests.get(url, params=params, timeout=15)
        resp.raise_for_status()
        prices = [p[1] for p in resp.json()["prices"]]
        btc_price = prices[-1]
        mayer = btc_price / np.mean(prices[-200:]) if len(prices) >= 200 else None
    except Exception as e:
        print(f"[WARN] BTC price fetch failed: {e}")
    
    # 8. 顶部警戒 mode 状态（复用 check_top_warning.py 的逻辑）
    top_warning_strong = 0
    top_warning_moderate = 0
    top_warning_etf_macro = 0
    top_warning_triggers = []
    
    if mvrv and nupl_from_mvrv and pi_cycle:
        if (mvrv > 3.0 and nupl_from_mvrv > 0.65 and pi_cycle["proximity"] < 0.05):
            top_warning_strong = 1
            top_warning_triggers.append("4 指标叠加 (MVRV + NuPL + Pi Cycle 接近)")
        elif pi_cycle["triggered"]:
            top_warning_strong = 1
            top_warning_triggers.append("Pi Cycle Top 触发")
        elif mvrv > 2.5 and nupl_from_mvrv > 0.55:
            top_warning_moderate = 1
            top_warning_triggers.append("MVRV + NuPL 中等叠加")
    
    if (etf_flow and etf_flow > 1e9 and mayer and mayer > 2.0):
        top_warning_etf_macro = 1
        top_warning_triggers.append("ETF 流入 > $1B + Mayer > 2.0")
    
    # 9. 写入 SQLite
    conn = sqlite3.connect(DB_PATH)
    cursor = conn.cursor()
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS onchain_metrics (
            metric_id INTEGER PRIMARY KEY AUTOINCREMENT,
            metric_date DATE NOT NULL,
            mvrv REAL,
            nupl REAL,
            puell REAL,
            pi_cycle_ratio REAL,
            pi_cycle_proximity REAL,
            pi_cycle_triggered INT,
            btc_etf_daily_flow_usd REAL,
            btc_price REAL,
            mayer_multiple REAL,
            btc_dvol REAL,
            top_warning_strong INT,
            top_warning_moderate INT,
            top_warning_etf_macro INT,
            top_warning_triggers TEXT,
            source TEXT,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
            UNIQUE(metric_date)
        )
    """)
    
    cursor.execute("""
        INSERT OR REPLACE INTO onchain_metrics
        (metric_date, mvrv, nupl, puell, pi_cycle_ratio, pi_cycle_proximity,
         pi_cycle_triggered, btc_etf_daily_flow_usd, btc_price, mayer_multiple,
         btc_dvol, top_warning_strong, top_warning_moderate, top_warning_etf_macro,
         top_warning_triggers, source)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
    """, (
        today,
        mvrv,
        nupl_from_mvrv,
        puell_from_cg,
        pi_cycle["ratio"] if pi_cycle else None,
        pi_cycle["proximity"] if pi_cycle else None,
        pi_cycle["triggered"] if pi_cycle else None,
        etf_flow,
        btc_price,
        mayer,
        dvol,
        top_warning_strong,
        top_warning_moderate,
        top_warning_etf_macro,
        json.dumps(top_warning_triggers),
        "coinmetrics+coinglass+deribit+coingecko"
    ))
    conn.commit()
    conn.close()
    
    print(f"[{today}] onchain_metrics updated:")
    print(f"  MVRV: {mvrv}, NuPL: {nupl_from_mvrv}, Puell: {puell_from_cg}")
    print(f"  Pi Cycle: ratio={pi_cycle['ratio'] if pi_cycle else 'N/A'}, triggered={pi_cycle['triggered'] if pi_cycle else 'N/A'}")
    print(f"  ETF flow: ${etf_flow/1e6:.0f}M" if etf_flow else "  ETF flow: N/A")
    print(f"  BTC: ${btc_price:.0f}, Mayer: {mayer:.2f}" if btc_price and mayer else "  BTC/Mayer: N/A")
    print(f"  DVOL: {dvol*100:.1f}%" if dvol else "  DVOL: N/A")
    print(f"  Top warning: strong={top_warning_strong}, moderate={top_warning_moderate}, etf_macro={top_warning_etf_macro}")
    print(f"  Triggers: {top_warning_triggers}")

if __name__ == "__main__":
    update_onchain_metrics()
```

- 所有"减半后 12-18 月顶部"经验规律为**机制推断**（供应减半经济学理由 + n=4 数据点），不是因果定律——承自外脑 #18 §13.1。
- 所有顶部警戒 mode 触发条件（4 指标叠加 + ETF + 宏观 5 维度）是**工程化触发器**——不是"机械预测"——需配合人工复盘。
- 期权对冲集成（Phase 1-3）依赖**项目实际资金 + 风险预算 + 监管合规**——本文给出框架，工程化实施需根据用户实际配置调整。
- 2025-10 顶部特殊性（指标集体失声 + ETF 主导）警示：**单指标 + 双指标叠加可能仍为弱信号**——必须用 ETF flow + 减半日历 + 监管反转 + 机构持仓 + 宏观 5 维度交叉判断（承自外脑 #18 §10.3）。
- 数据点（4 次减半日 / 顶部日 / 链上指标 / ETF flow）以 2026-08-31 行情为准；**费率与熔断线参数以 Gate.io 实测账户和外脑 #6 架构初稿 v0.1 为准**。
