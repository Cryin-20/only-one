## 可复用原则（决策时引用）

1. **决策记录 ≠ 决策日志**：决策记录是单条决策的完整快照（一份 md 文件），决策日志是所有决策记录的归档（按年月组织的文件夹）。**先写单条记录，再纳入日志管理**——前者保证质量，后者保证复盘节奏。
2. **pre-mortem 的"6 个月"不是随意的数字**：Klein 1989/2007 提出的 6 个月时间窗是一个**心理机制**——足够长到让"未来人"产生距离感（不是现在还在热血的你），又足够短到让"未来人"仍能记得当时的决策背景。这是 pre-mortem 能暴露盲点的核心机制。
3. **监测信号必须独立于情绪**：退出条件不能是"我觉得不对劲"——必须是**可观测的硬指标**（价格、波动率、频率、阈值）。情绪会骗人，指标不会。把"我会害怕吗"换成"过去 30 天均值跌破 X"——后者才是真正的退出信号。
4. **贝叶斯更新需要"承诺触发器"**：决策时同步写下"如果哪个信号出现我就重新评估"——这是 WRAP 第四步"Prepare to be wrong"的最低成本版本，也是 #6 决策清单 §5.4 触发器的**执行落地**。没有承诺触发器的决策 = 黑盒决策——3 个月后你都不知道当初为什么这么选。
5. **复盘节奏 = 1 周 / 1 月 / 3 月 / 1 年**：1 周看反向压力是否触发（"我是不是真的撤了"）；1 月看核心假设是否成立（"市场 / 项目 / 职业的实际反馈"）；3 月看偏差自检是否准确（"我是否真的被 X 偏差影响"）；1 年看完整闭环（"我学到了什么，下次决策会改什么"）。**不写下来 = 永远在重复同样的决策错**。
6. **成功的决策 + 失败的决策都要归档**：不是"只写失败"才是复盘——成功决策要找出"是英明还是运气"，失败决策要找出"是哪种偏差"。**两个方向都是贝叶斯更新证据**，单方向的复盘会高估自己的能力（幸存者偏差）。
7. **Blameless 是原则，不是宽容**：U.S. Army AAR 和 Google SRE Postmortem 的核心精神是"找系统原因、不找人原因"——但**不找个人原因 ≠ 不追个人责任**。责任要明确到"谁在什么时候做什么"，但失败要归到"系统假设 / 流程设计 / 信息流向上"。
8. **决策记录的"11 个核心字段"是肌肉记忆**：决策时不需要每次都重新设计字段表——把 11 个字段固定下来（决策标题 / 日期 / 类型 / 摘要 / 触发条件 / 核心假设 / pre-mortem / 反向压力 / 偏差自检 / 监测信号 / 复盘节奏），**重复填就是重复练习**——5 分钟后系统 2 就自动接管。
9. **决策记录不是给"现在的你"看的**：它是给 6 个月后的你 + 1 年后的你 + 同伴 / 团队 / 未来的 AI agent 看的——所以**写的时候要假设读者不知道这件事的来龙去脉**。这条原则决定了你写多少上下文。
10. **决策记录的成本必须低于决策本身的成本**：写一份记录 5-10 分钟，决策本身从立项到完成可能 1 周-1 年——记录的边际成本极低。不要因为"今天好忙"就跳过——**跳过决策记录的决策 = 没做决策**（3 个月后你和路人一样不知道当初为什么这么选）。

## 核心逻辑链

1. **前提**：决策完成只是"做完分析"，**真正的决策质量要等复盘才能评判**——而复盘需要记录，没有记录的复盘 = 靠记忆复盘 = 后见之明偏差 + 峰值-终值法则 + 自我服务偏差三重污染（承自《认知偏差全谱》§B/G/F 组）。
2. **机制一（决策记录 = 外部化记忆）**：人脑的记忆不可靠（Schacter 1999 七宗罪），把决策的"理由 + 假设 + 退出条件"写到文件里 = 把决策的关键信息从脆弱的人脑迁移到持久的文件系统。这是**最便宜的"贝叶斯更新基础设施"**——未来任何时刻需要更新判断，都能查到当时的依据。
3. **机制二（pre-mortem 强制暴露盲点）**：Klein 1989/2007 的核心洞察是"在执行前强制想象失败，比乐观分析更能暴露盲点"——因为乐观分析走的是系统 1（快、自动、有偏），而 pre-mortem 强制走系统 2（慢、刻意、有距离感）。6 个月的时间窗制造的距离感是关键——让你能像"未来人"一样审视当时的决策。
4. **机制三（反向压力测试找假设组合）**：决策依赖多个假设，但单假设错常常能扛，**双假设错常常是归零**——这是 3AC/FTX/LUNA 等加密崩溃的共同模式（承自《自动量化加密货币的成功与失败》§3）。决策记录强制把"我依赖的 3-5 个关键假设"写下来，并把"哪两个假设同时错"作为退出条件。
5. **机制四（贝叶斯更新的承诺触发器）**：每个重大决策时**承诺一个外部触发器**让未来的你能更新判断——承自《如何用概率观看待和理解世界》"贝叶斯迭代"和 #6 决策清单 §5.4 的 4 类触发器。决策记录把这 4 类触发器固定为字段，未来执行有据可查。
6. **机制五（复盘节奏协议）**：复盘不是"想起来就看看"，是**制度化的 1 周 / 1 月 / 3 月 / 1 年节奏**——U.S. Army AAR、Google SRE Blameless Postmortem 都是这种节奏（"AAR 是动词不是名词"）。每个节奏有不同的检查清单（见第五章）。
7. **结果**：决策记录 + pre-mortem + 反向压力 + 偏差自检 + 监测信号 + 复盘节奏 = **完整的"决策闭环"**。任何重大决策走过这套闭环，复盘就有证据可循，未来的判断就能在历史数据上迭代。
8. **行动指引**：① 决策完成后立刻（24h 内）填写模板 → ② 归入决策日志（`D:\decision-log\YYYY-MM\`）→ ③ 1 周 / 1 月 / 3 月 / 1 年按节奏复盘 → ④ 复盘结论归档为"贝叶斯更新证据"，更新未来决策的"先验概率"。
9. **诚实声明**：本文不直接读 Klein 1998《Sources of Power》、Kahneman 2011《Thinking, Fast and Slow》、Heath 2013《Decisive》原书章节；Klein pre-mortem 的核心描述基于 gary-klein.com 官方页面 + Rock.so + The Uncertainty Project + GetAlfred 多源交叉验证；WRAP 框架基于 ModelThinkers + LITFL + Stanford GSB 综述 + LinkedIn + Happy Brain Science 多源；Bezos Type 1/Type 2 基于 Farnam Street + SEC 原始 shareholder letter；Cynefin 基于 Wikipedia + thecynefin.co 官方 + untools.co；AAR 基于 Thayer Leadership 2026 官方 + 4 个 Army AAR 模板综述；Blameless Postmortem 基于 sre.google/sre-book/postmortem-culture/ + incident.io + Conf42；10-10-10 基于 Oprah + Inc + Mindsera。

## 分章笔记

### 第一章　决策记录模板的核心结构（11 个字段详解）

> **设计原则**：下面的 11 个字段是"决策时填写"的最小集。每个字段都有"为何需要"+"填什么"+"反例"三段。**复盘时只需要重新读这 11 个字段就能完整还原决策**——不需要翻原始资料。

#### 字段 1：决策标题 + 日期

**填什么**：用一句话描述决策（动名词结构），日期精确到日。

```
决策标题：启动 Phase 1 费率套利 paper trading
日期：2026-09-15
```

**反例**：标题写成"费率套利决定"太宽泛；写成"决定做费率套利"是动词结构，未来回看不知道是什么上下文。

#### 字段 2：决策类型（Cynefin 域）

**填什么**：标注这次决策属于 4 个 Cynefin 域之一（Wikipedia "Cynefin framework" + thecynefin.co 官方 + untools.co 综述）：

| Cynefin 域 | 特征 | 适用方法 |
| --- | --- | --- |
| **Clear（清晰）** | 因果已知，最佳实践可用 | 直接套用清单 / 规则 |
| **Complicated（繁杂）** | 因果需专家分析 | 找专家 / 多视角分析 |
| **Complex（复杂）** | 因果只能后视 | 涌现实验 / 小试点 |
| **Chaotic（混沌）** | 无因果，急需行动稳定局面 | 立刻行动 → 移到 Complex |

```
决策类型：Complex（用小试点 paper trading 验证费率套利假设）
```

**反例**：把"启动费率套利"标成 Clear（错——因为费率套利的历史成功率未知）→ 会导致"套用最佳实践"而忽略验证。

#### 字段 3：决策摘要（一句定性）+ 关键参数

**填什么**：1 句话定性 + 3-5 个量化参数。

```
决策摘要：100 USDT 项目 Phase 1 起步，跑 BTC/USDT 费率套利（Gate 永续 1x 隔离保证金 + 现货多），目标 30 天均值 ≥ 0.01%/8h 才开仓
关键参数：本金 100 USDT / 单币 ≤ 10 USDT / 日亏熔断 -2% / 组合回撤熔断 -10%
```

**反例**：摘要写成"决定做费率套利"（无量化参数）→ 6 个月后复盘时无法对比"实际发生了什么 vs 当时预期什么"。

#### 字段 4：触发条件（为什么现在做，6 类触发器之一）

**填什么**：从 #6 决策清单的 6 类触发器里选一类（不可逆 / 资源 > 5% / 承诺 > 6 月 / 多方案选型 / 阶段跃迁 / 重大金额交易），并写出"为什么是现在"。

```
触发条件：项目阶段跃迁（Phase 0 验收完成 → 跨进 Phase 1 费率套利）
为什么是现在：Phase 0 的 P0-3 数据管道已经积累 2 周观测数据，确认 Gate BTC 30 天均费率 ≈ 0.004% < 0.01% 开仓线，进入 WAIT_LOW 观望期；Phase 1 paper trading 不动资金，符合"先建反脆弱结构再追求收益"的项目原则
```

**反例**：触发条件只写"开始 Phase 1"——6 个月后复盘不知道"当时为什么不等观测数据更长"。

#### 字段 5：核心假设（3-5 条，"我假设 X 因为 Y"）

**填什么**：列出决策依赖的 3-5 个关键假设，每个假设给"因为 Y"的支撑。

```
核心假设：
1. 我假设 BTC 资金费率 30 天均值能稳定 ≥ 0.01%/8h → 因为 2 周观测显示 ≈ 0.004%，但 crypto 市场长期均值约 0.01%（承自《自动量化加密货币的成功与失败》§6）
2. 我假设 1x 隔离保证金的强平线足够安全 → 因为 Gate BTC 30 天最大日内波动 ≈ 8%，1x 不会被强平
3. 我假设 Gate.io 不暴雷 → 因为 Gate 主流所 + 80% 返点 + 资产 ≤ 50% 原则（承自《自动量化项目架构初稿》L0）
4. 我假设费率反转信号能及时捕捉 → 因为 30 天均值 + 连续 2-3 个结算周期转负清仓是标准动作
5. 我假设 paper trading 能真实模拟实盘滑点 → 因为只用 CCXT 市价单 + Gate maker 优先
```

**反例**：假设写成"费率能涨"——太模糊，无法验证；正确是"30 天均值 ≥ 0.01%/8h"——可观测、可触发清仓。

#### 字段 6：pre-mortem（Klein 2007）

**填什么**：用 Klein 1989/2007 的 pre-mortem 模板（gary-klein.com 官方页面 + The Uncertainty Project + Rock.so 综述）——**想象"6 个月后这次决策失败了，最可能的 3 个原因"**。

```
pre-mortem（6 个月后这次决策失败了，最可能的 3 个原因）：
1. 费率长期低于 0.01%/8h 开仓线 → paper trading 2 周无信号 → 浪费时间
2. 实际滑点比预期高 3x（Gate maker 流动性假象）→ paper 收益 -50% → 不可持续
3. Gate 突然调整 maker 返点从 80% 到 40% → 收益减半 → 商业模式失效

我现在在规避这 3 个失败原因吗？
1. 部分规避——设定"2 周无信号自动停止 paper trading"，不无限等
2. 部分规避——L2 数据层会记录每次成交的实际滑点，paper trading 阶段建立基线
3. 未规避——Gate 返点政策是对手方风险，目前没应急方案
```

**核心心理机制**（来自 Klein 2007 + GetAlfred 解读）：pre-mortem 的 6 个月时间窗**制造距离感**——让"未来人"能更客观地审视"当时的热血决定"。这是 pre-mortem 比乐观分析更能暴露盲点的核心。

**反例**：pre-mortem 写成"如果失败了我就再做一个"——这是"反应"不是"原因"。正确是"什么**系统因素**会导致失败"——比如费率反转、滑点、对手方风险。

#### 字段 7：反向压力 / 退出条件（3-5 条硬指标）

**填什么**：3-5 条**可观测的硬指标**——触发即退出/修正/重新评估。

```
反向压力 / 退出条件：
1. paper trading 2 周内 0 次成交 → 暂停，回到观测期
2. 单笔成交实际滑点 > 0.05% → 停止 paper，回归 maker 单优化
3. Gate maker 返点 < 50% → 重新评估交易所选择
4. 30 天均费率连续 7 天 < 0.005% → 暂停 paper 1 个月
5. 组合回撤 > -10% → 全停 + 人工复盘
```

**反例**：写成"如果感觉不对劲就退出"——这是"情绪触发"不是"硬指标"，无法 24/7 自动执行。

#### 字段 8：偏差自检（对照认知偏差全谱 F/G/H 组逐项扫）

**填什么**：把决策时最可能影响的 3-5 个偏差列出来，每个偏差给"我可能被 X 偏差影响，因为……"。

```
偏差自检（对照《认知偏差全谱》F/G/H 组）：
1. 确认偏差（F）——我可能只看了"费率套利成功的案例"，没看"费率套利失败案例"（3AC/GBTC 套利、LUNA 死亡螺旋）
2. 过度自信（F）——我对费率能稳定在 0.01%/8h 的确信度实际只有 50%，但我刚才说"肯定能"
3. 可得性启发式（A）——我最近读了太多"费率套利是无风险套利"的帖子，可能高估了真实收益稳定性
4. 沉没成本（F）——我已经为 Phase 0 投入了 60 小时+ 一些云服务器费用，可能不想承认"白做了"
5. 现状偏差（D）——我可能不想放弃"我在做的项目"，即使环境已变
```

**核心洞察**（承自《认知偏差全谱》§5 反偏差策略）：**知道 ≠ 躲开**——把"我可能被 X 偏差影响"写在决策记录的开头，是最低成本的反偏差动作。

**反例**：偏差自检只写"我挺客观的"——这是动机性推理（F 组）的典型表现，正确是"我此刻最不可能看到的盲点是哪个"。

#### 字段 9：监测信号 + 触发器（每个反向压力配一个可观测信号）

**填什么**：每个反向压力配一个**可观测的硬指标 + 自动触发方式**。

```
监测信号 + 触发器：
1. paper trading 2 周无成交 → 飞书告警（每日早报统计）→ 触发 L5 暂停逻辑
2. 单笔滑点 > 0.05% → 实盘 paper 阶段的 CCXT 数据自动记录 + 飞书日推统计 → 触发 L1 熔断检查
3. Gate 返点 < 50% → Gate API 每日检测 + 飞书周报 → 触发"重新评估交易所"清单
4. 30 天均费率 < 0.005% → L2 数据层每日计算 + 飞书日推 → 触发 L5 自动暂停
5. 组合回撤 > -10% → L1 风控层实时监控 + 飞书立即告警 → 触发全停
```

**关键**（承自 #6 决策清单 §5.4 触发器）：**没有承诺触发器的决策 = 黑盒决策**。承诺触发器 + 自动触发方式 = 把"我会反悔吗"从意志力问题变成系统问题。

**反例**：监测信号写成"我会盯着"——意志力问题；正确是"飞书每日 9:00 自动推送昨日统计 + 阈值触发告警"。

#### 字段 10：承诺（WRAP 第 4 步 "Prepare to be wrong"）

**填什么**：决策时同步写下"如果哪个信号出现我就反悔/重新评估"——WRAP 第四步"Prepare to be wrong"（ModelThinkers + LITFL + Stanford GSB 综述）。

```
承诺（WRAP 第 4 步）：
1. 如果 paper trading 2 周无成交 → 我承诺立即暂停，回到观测期（不"再等一周看看"）
2. 如果 Gate 返点 < 50% → 我承诺重新评估交易所（不"先这样吧"）
3. 如果组合回撤 > -10% → 我承诺全停 + 人工复盘（不"等等会反弹"）
4. 如果 30 天均费率连续 7 天 < 0.005% → 我承诺暂停 paper 1 个月（不"这次不一样"）
```

**关键洞察**（承自 Heath《Decisive》）：WRAP 的第四步"Prepare to be wrong"——核心是**在决策时主动设计"我错"的场景**，让"我错"成为一个**有准备的退出**而不是被现实击穿的崩盘。

**反例**：承诺写成"如果感觉不对就停"——和偏差自检一样，是情绪触发。正确是"如果 X 信号出现"——可观测 + 可自动触发。

#### 字段 11：复盘节奏（决定什么时候 review）

**填什么**：1 周 / 1 月 / 3 月 / 1 年的具体检查清单（见第五章详细协议）。

```

```

**反例**：复盘节奏只写"以后看看"——这等于"永远不复盘"。正确是**日历上锁死 4 个时间点**。

#### 字段 12：关联（链接到反脆弱决策清单 #6 对应的触发场景与全谱问题）

```markdown
- 反脆弱决策清单 #6 场景：A 组不可逆决策（A1/A2/A3/A7）+ C 组跨时段承诺（C1/C2/C3）+ §3.2 职业领域 9 条
```

### 第四章　模板示例 3：消费类（是否买一辆 30 万的车）

> **场景**：30 岁家庭，有娃，存款 50 万 RMB，考虑买一辆 30 万的家庭用车（不是投资类，是消费类）。决策触发器 = 重要资源调配（B 组）+ 杠杆/借币考量（F 组）。

```markdown
# 决策记录：是否买一辆 30 万的家庭用车

## 1. 元信息
- 决策标题：购买 30 万家庭用车（全款 vs 贷款 3 年的对比）
- 日期：2026-11-01
- 决策类型：Clear（消费类决策有明确选项，可套用清单）
- 决策摘要：30 万购车预算；全款付影响存款 -60%；贷款 3 年月供 +8000；目标解决有娃后通勤 + 周末出行需求
- 关键参数：购车预算 30 万 / 现有存款 50 万 / 月供 8000（贷款方案）/ 年保险 + 保养 ≈ 1.5 万 / 油费 + 停车 ≈ 1 万/年 / 折旧首年 -15%

## 2. 触发条件
- 6 类触发器之一：重要资源调配（B 组，30 万 > 总存款 50%）
- 为什么是现在：孩子 1 岁半，出门打车越来越不便；公共交通带娃出门 1 次 = 兵荒马乱；妻子周末带娃回娘家需要车

## 3. 核心假设（5 条）
1. 我假设 30 万的车能解决"有娃通勤 + 周末出行"的核心需求 → 因为当前打车 + 公交确实不便
2. 我假设全款 vs 贷款的总成本差 ≈ 1.5 万（贷款利息）→ 因为 3 年 8000 × 36 = 28.8 万，比全款多 1.5 万
3. 我假设车的折旧速度 ≈ 首年 -15% → 因为二手车市场公开数据 + 汽车之家估值
4. 我假设养车成本（保险 + 保养 + 油 + 停车）≈ 2.5 万/年 → 因为周围车主反馈 + 行业平均
5. 我假设不买车的"机会成本"（继续打车 + 公交）≈ 1.5 万/年 → 因为打车通勤 + 周末出行频次估算

## 4. pre-mortem（6 个月后后悔的 3 个原因）
1. 车 90% 时间停在车库——使用率 < 30% → 30 万 / 5 年 = 6 万/年（不折旧）→ 不如租车
2. 养车成本超预算——停车 + 罚单 + 意外维修 → 实际成本 4 万/年 vs 预算 2.5 万
3. 车的折旧让我"心理上亏了"——30 万买 1 年后变 25.5 万 → 看着贬值心疼

我现在在规避这 3 个原因吗？
1. 部分规避——我已记录"过去 3 个月打车 / 公交出行频次"，数据支持"车使用率会 > 30%"
2. 部分规避——已问 3 个有车的同事，了解他们的实际养车成本
3. 未规避——折旧是车的固有属性，无法规避；可以选"保值率高的车型"（德系 / 日系）

## 5. 反向压力 / 退出条件（5 条硬指标）
1. 实际使用率 < 30% → 启动"卖车 / 换租车"评估
2. 养车成本连续 3 个月超预算 → 启动"重新评估"
3. 贷款 1 年后月供影响生活质量 → 启动"提前还贷"评估
4. 车出现重大故障（维修 > 5 万）→ 启动"卖车"评估
5. 家庭月可支配收入因车减少 > 20% → 启动"重新评估"

## 6. 偏差自检（对照认知偏差全谱 F/G/H 组）
1. 社会证明（E）——"周围人都买车了"让我觉得"我也应该买"，但他们的需求和我不同
2. 锚定效应（A）——"30 万购车预算"是锚，让我忽略"15 万也能满足 80% 需求"
3. 损失厌恶（D）——不买 = "继续打车不便"的损失感，让我更想赶紧买
4. 框架效应（D）——4S 店把"贷款"框成"无压力"，但本质是债务
5. 心理账户（H）——"买车是改善生活"的账户让我不愿把"30 万 / 5 年 = 6 万/年"和"打车 1.5 万/年"对比

## 7. 监测信号 + 触发器
1. 使用率 → 每月 1 次自我记录（出车次数 / 总可出车次数）→ 触发"卖车"评估
2. 养车成本 → 记账 app 自动统计 → 触发"重新评估"清单
3. 月供影响 → 每月家庭财务对账 → 触发"提前还贷"评估
4. 故障维修 → 4S 店报价单 → 触发"卖车"评估
5. 家庭可支配收入 → 月度统计 → 触发"重新评估"

## 8. 承诺（WRAP 第 4 步）
1. 如果使用率 < 30% → 我承诺启动"卖车 / 换租车"评估（不"再等等看"）
2. 如果养车成本超预算 → 我承诺重新评估（不"已经买了先用着"）
3. 如果月供影响生活质量 → 我承诺提前还贷（不"按合同继续"）
```

### 第五章　复盘节奏协议（1 周 / 1 月 / 3 月 / 1 年的检查清单）

> **核心原则**（承自 U.S. Army AAR + Google SRE Blameless Postmortem + Thayer Leadership 2026 官方版）：**AAR 是动词不是名词**——复盘是一个持续动作，不是一次性事件。每个时间点有不同的检查清单，不是简单的"打开看一遍"。

#### 5.1 1 周后：检查反向压力是否触发

**目的**：验证反向压力的"灵敏度"——是太松（该触发没触发）还是太紧（不该触发也触发）。

**检查清单**：

| # | 检查项 | 通过标准 | 不通过的处理 |
| --- | --- | --- | --- |
| 1 | 反向压力是否触发？ | 0 条触发（说明决策仍在轨道） | 如触发，启动"退出 / 修正"流程 |
| 2 | 监测信号是否正常推送？ | 飞书 / 邮件正常收到 | 如未收到，检查监测系统 |
| 3 | 核心假设是否仍成立？ | 全部成立 | 如有变化，记录在案 |
| 4 | 我是否"感觉不对劲"？ | 没有 | 如有，启动 5 分钟暂停（承自 #6 决策清单 §4 决策中校验） |
| 5 | 偏差自检是否仍准确？ | 准确 | 如发现新的偏差，补到决策记录 |

**输出**：在决策记录末尾追加 1 行（YYYY-MM-DD 1-week review）+ 5 项打勾/未打勾。

#### 5.2 1 月后：检查核心假设是否成立

**目的**：从"短期反馈"到"中期验证"——核心假设需要 30 天数据才能初步判断。

**检查清单**：

| # | 检查项 | 通过标准 | 不通过的处理 |
| --- | --- | --- | --- |
| 1 | 核心假设 1-5 各自成立度 | ≥ 3/5 成立 | < 3/5 → 启动"重新评估"流程 |
| 2 | pre-mortem 列出的 3 个失败原因 | 都未发生 | 任何一个发生 → 启动对应退出条件 |
| 3 | 实际进展 vs 关键参数 | 在参数范围内 | 超出 → 修正关键参数 |
| 4 | 我是否仍认同这个决策？ | 认同 | 不认同 → 启动"主动修正" |
| 5 | 新出现的偏差或风险？ | 无 | 有 → 补到偏差自检 + 监测信号 |

**输出**：在决策记录追加 1 月 review + 核心假设验证结论。

#### 5.3 3 月后：检查偏差自检是否准确

**目的**：从"中期验证"到"偏差校准"——3 个月足够看出决策时的高估 / 低估。

**检查清单**：

| # | 检查项 | 通过标准 | 不通过的处理 |
| --- | --- | --- | --- |
| 1 | 决策时列的 5 个偏差，哪个真的影响了？ | 列出 1-3 个 | 如 ≥ 4 个真的影响 → 决策过程需重大修正 |
| 2 | 我是否高估 / 低估了什么？ | 偏差 ≤ 30% | 偏差 > 30% → 标注"严重偏差" |
| 3 | 退出条件是否在对的时机触发？ | 准时触发 | 误触发 → 修正退出条件；漏触发 → 收紧条件 |
| 4 | 监测信号是否有效？ | 有效（触发时是真实问题） | 失效 → 修正监测方式 |
| 5 | 我学到了什么？ | 写下 3 条 | 没学到 → 决策记录本身可能有问题 |

**输出**：在决策记录追加 3 月 review + 偏差校准结论（"下次决策我会改什么"）。

#### 5.4 1 年后：完整复盘

**目的**：从"短期反馈 + 中期验证 + 偏差校准"到"完整闭环"——1 年是大多数决策的完整生命周期（项目类决策对应 Phase 1-2 周期；职业类决策对应 1 年合同周期；消费类决策对应车的"1 年折旧周期"）。

**检查清单**（参考 U.S. Army AAR 四问 + Google SRE Blameless Postmortem 模板 + Thayer Leadership 2026 官方版）：

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | **What was the plan?** | 决策时写的"决策摘要"和"关键参数" |
| 2 | **What actually happened?** | 实际发生了什么 + 关键参数的最终值 |
| 3 | **Why did it happen?** | 假设验证：哪些假设对了？哪些错了？为什么？ |
| 4 | **What did we learn?** | 我学到了什么 + 下次决策会改什么 |
| 5 | **What do we do with this information?** | 这次决策如何更新我的"先验概率" + 影响哪些未来决策 |

**输出**：完整的复盘文档（独立的 md 文件，归档到 `D:\decision-log\YYYY-MM\YYYY-MM-DD_标题_1y-review.md`）+ 决策记录标注"已完整复盘"。

#### 5.5 复盘输出格式：成功 + 失败都要归档

**关键**（承自 #6 决策清单 §5.3 + Google SRE Blameless Postmortem 哲学）：**成功的决策 + 失败的决策都要归档**——

| 决策结果 | 归档重点 | 贝叶斯更新方向 |
| --- | --- | --- |
| **成功的决策** | 是英明还是运气？过程可重复吗？ | 如果是"英明" → 提高未来类似决策的先验概率；如果是"运气" → 不调整 |
| **失败的决策** | 是哪种偏差？是哪个假设错了？ | 如果是"系统因素" → 调整未来类似决策的退出条件；如果是"运气" → 不调整 |

**反例**（承自《认知偏差全谱》§F 自我服务偏差）："成功的归自己，失败的归运气"——这是**最常见的偏差**，会导致"先验概率系统性偏高"。Blameless Postmortem 的核心精神就是**找系统原因、不找人原因**——但**不找个人原因 ≠ 不追个人责任**，责任要明确到"谁在什么时候做什么"，但失败要归到"系统假设 / 流程设计 / 信息流向上"。

### 第六章　决策日志管理（文件夹结构 + 命名规则 + 检索方法）

> **设计原则**：决策记录是"单条决策的完整快照"，决策日志是"所有决策记录的归档"。**先写单条记录（5-10 分钟），再纳入日志管理**——前者保证质量，后者保证复盘节奏。

#### 6.1 文件夹结构

```
D:\decision-log\
├── YYYY-MM\                          # 按年月归档（每月一个文件夹）
│   ├── YYYY-MM-DD_标题.md            # 单条决策记录
│   ├── YYYY-MM-DD_标题_1y-review.md  # 1 年复盘文档
│   └── ...
├── index.md                          # 所有决策的索引（首行最新）
├── templates\                        # 模板文件
│   └── decision-record.md            # 第一章 11 字段模板
└── archive\                          # 归档（决策 > 5 年的）
    └── ...
```

#### 6.2 命名规则

| 文件类型 | 命名格式 | 示例 |
| --- | --- | --- |
| 决策记录 | `YYYY-MM-DD_标题.md` | `2026-09-15_启动费率套利-paper-trading.md` |
| 1 年复盘 | `YYYY-MM-DD_标题_1y-review.md` | `2027-09-15_启动费率套利-paper-trading_1y-review.md` |
| 季度复盘 | `YYYY-MM-DD_标题_Qn-review.md` | `2026-12-15_启动费率套利-paper-trading_Q3-review.md` |

**反例**：命名写成"决策记录.md" / "第一个决策.md"——无法检索，无法排序。

#### 6.3 index.md 索引

```markdown

## 全部决策（新 → 旧）

| 日期 | 标题 | 决策类型 | 关键参数 | 复盘进度 |
| --- | --- | --- | --- | --- |
| 2026-11-01 | 是否买 30 万的家庭用车 | Clear | 30 万 / 全款 vs 贷款 | 待 1 周 |
```

**维护规则**：每次新建决策记录 → 在 index.md 表格首行插入一行 + 主题小节追加一行（增量更新，不整篇重写）。

#### 6.4 检索方法

**3 种检索方式**（按使用频率排序）：

1. **按主题**（投资 / 职业 / 项目 / 健康 / 育儿 / 关系）：打开 index.md → 找对应小节 → 找最近 3 条。
2. **按日期**（"3 个月前的那个决定是什么"）：打开 index.md → 表格里找日期 → 打开决策记录。
3. **按关键词**（"费率套利 / 996 / 30 万"）：用 grep / ripgrep 全文搜索 `D:\decision-log\`。

**关键**（承自《认知偏差全谱》§B 记忆偏差）：**人脑的记忆不可靠**（Schacter 1999 七宗罪）——3 个月后"我当初为什么这么决定"的标准答案常常被扭曲。决策日志的检索系统是**对抗记忆偏差的工程方案**。

### 第七章　与 #6 反脆弱决策清单的闭环（前清单 → 后记录）

> **核心闭环**：决策科学不是"分析 → 决策"的单向过程，是"前清单 → 决策 → 后记录 → 复盘 → 前清单更新"的双向闭环。

#### 7.1 闭环结构图

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   #6 反脆弱决策清单（前清单）                              │
│   ↓                                                      │
│   决策执行                                                │
│   ↓                                                      │
│   本文决策记录模板（后记录）                              │
│   ↓                                                      │
│   1 周 / 1 月 / 3 月 / 1 年 复盘                         │
│   ↓                                                      │
│   贝叶斯更新（更新前清单）                                │
│   ↓                                                      │
│   回到 #6 反脆弱决策清单                                  │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

#### 7.2 前清单的"决策前 5 分钟"

承自 #6《反脆弱决策清单》§6 A4 卡片版：

- **触发器**（命中即用）：不可逆 / 资源 > 5% / 承诺 > 6 月 / 候选 ≥ 3 / 阶段跃迁 / 触及熔断线 30%+
- **12 条核心问题**：凸性 / 可选择性 / 杠铃 / 冗余 / via negativa / 规模 / 学习 / 偏差 / 偏差 / 反向 / 触发器

**任何重大决策前 5 分钟过一遍**——命中触发器 → 走完整清单；不命中 → 跳过。

#### 7.3 后记录的"决策后 24 小时 + 1 周 / 1 月 / 3 月 / 1 年"

承自本文第一章 11 字段 + 第五章复盘节奏：

- **决策后 24 小时**：填写 11 字段（5-10 分钟）→ 归档到决策日志
- **1 周后**：检查反向压力是否触发
- **1 月后**：检查核心假设是否成立
- **3 月后**：检查偏差自检是否准确
- **1 年后**：完整复盘 + 贝叶斯更新

#### 7.4 闭环的"贝叶斯更新"机制

**关键洞察**（承自《如何用概率观看待和理解世界》"贝叶斯迭代"）：决策记录的真正价值不是"记录当时"，是**让未来的你能在历史数据上迭代判断**——

| 决策结果 | 贝叶斯更新方向 | 影响 |
| --- | --- | --- |
| 决策成功 + 假设正确 | 提高未来类似决策的"先验概率" | 让"项目类" / "职业类" / "消费类"决策的下一次更有信心 |
| 决策成功 + 假设错误（运气） | 不调整先验概率 | 防止"幸存者偏差"过度自信 |
| 决策失败 + 假设错误 | 降低未来类似决策的先验概率 | 修正"过度自信" |
| 决策失败 + 假设正确（系统因素） | 不调整先验概率，调整"退出条件" | 强化"反脆弱组织设计" |

#### 7.5 闭环的工程实现：决策记录 → 决策日志 → 反脆弱决策清单

**实操流程**：

1. **决策前**：用 #6 反脆弱决策清单 §6 A4 卡片版过一遍
2. **决策中**：用 #6 决策清单 §4 决策中校验清单在 30-50% 时暂停
3. **决策后 24h**：用本文模板填写 11 字段 → 归档到决策日志
4. **1 周 / 1 月 / 3 月 / 1 年**：用第五章复盘节奏检查清单
5. **复盘结论**：更新 #6 决策清单的"先验概率"——例如"费率套利 paper 1 年后成功率从 50% 提升到 80%"，下次决策时直接调整。

**关键**（承自 #6 决策清单 §5.4 触发器）：**没有承诺触发器的决策 = 黑盒决策**。闭环的工程实现让"承诺触发器"从"今天的我"传递给"未来的我"，这是**最低成本的"决策基础设施"**。
