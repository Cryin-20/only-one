## 可复用原则（季度决策时引用）

1. **季度复盘不是"周评估 ×13"，是"看趋势"**：周评估看单点（这周做对了几个？哪些偏差触发了？），季度复盘看分布（12 周的分数曲线是上升、平、还是下降？哪种偏差出现频次从第 1 周到第 13 周是在收敛还是在发散？）。**单点可以靠运气，趋势骗不了人**——这正是周复盘"光快但看不到进步"的核心盲点。承自外脑《复利与非线性回报》§"复利的 4 个边界条件"——季度复盘是"跨周期稳定"的最低成本监测器。

2. **数据源决定天花板**：季度复盘的质量取决于数据源覆盖——只有 decisions/（决策数量）会漏掉"行为过程"，只有 weekly/（评估摘要）会漏掉"原始决策上下文"，只有 inbox json 会漏掉"嵌入 LLM 已写过一次的总结"。**3 个数据源必须并联**（decisions + weekly + inbox processed）——任何一个缺失都会让季度报告退化成"周评估 ×13"。

3. **4 维度评估框架固定下来才有效**：进步线趋势（3 维分数 12 周曲线）+ 偏差演化（19 条偏差 12 周分布）+ 决策质量（6 类触发器占比 + pre-mortem 命中率）+ 行为纪律机制使用（5 大机制每周触发频次）。**4 维度就是 4 把尺子**——任何一把缺失就看不到那一面；这把 4 尺子一旦固定，季度报告就能直接做"同比 vs 环比"，让"今年 Q3 vs 去年 Q3"的进步可量化。承自外脑 #8 第五章"复盘节奏协议"——1 周 / 1 月 / 3 月 / 1 年的不同节奏对应不同检查清单，季度 = 3 月节奏的工程化产物。

4. **LLM 二次分析的 prompt 必须有"上下文窗口预算"**：12 周的 weekly/ 单是 markdown 平均 2KB / 篇，13 篇 = 26KB；decisions/ 每周平均 3-5 条 × 800 字节 = 约 4KB × 13 周 = 52KB；inbox processed 飞书原始 json 每周约 10 条 × 200 字节 = 2KB × 13 = 26KB。**总输入 ~104KB**——必须做"采样 + 截断 + 优先级"。优先级策略：weekly 全部 → decisions 按"偏差标注数 ≥ 2"过滤 → inbox 按"decision-type != 'idle'"过滤。LLM 单次 prompt 不要超过 30KB（MiniMax-M3 max_tokens=4096 的安全上下文）。

5. **人工干预点是反幻觉的最后一道闸**：LLM 评估偏差演化、决策质量时，会因为"上下文不足"做出过度概括。**3 处必须人工 review**：① 趋势反转点（如某周分数突然从 3 跳到 1）→ 人工确认是"真退步"还是"评估标准更严"；② 偏差类型分布的"新增偏差"（前 11 周没触发 Q4 突然出现）→ 人工确认是"新场景触发"还是"LLM 误分类"；③ 下季度锚点 → 人工 confirm 是否真的"够具体 + 可执行"。**没有人工 review 的季度报告 = 学术论文，不是操作手册**。

6. **报告长度 vs 阅读频率成反比**：周评估 400-600 字（每周日读 5 分钟）；月度报告 1500-2500 字（每月读 15 分钟）；**季度报告 3000-5000 字 + 12 页结构**（每季度读 30 分钟 + 飞书金色卡预览 1 分钟）。长 = 深；短 = 浅；季度复盘的"长"不是冗余，是"12 周 + 4 维度 + 多页可视化"的必然结果——但要靠"目录 + 跳转"降低阅读阻力（每页最后一行加"详见第 N 页 §X.Y"）。

7. **飞书推送频率匹配阅读场景**：周评估 → 紫色卡（每周日晚 22:30，周日有空精读）；月度 → 橙色卡（月末周日晚 21:30 后）；**季度 → 金色卡（季度最后一周日 23:00，工作日没空精读）**。颜色对应重要性递增——紫色"参考" / 橙色"留意" / 金色"必须看"。卡片标题固定格式：`📊 Q{季度}-{年} 季度复盘 ({决策数} 条 / {weeks} 周)`，让用户一眼判断"这次的规模"。

8. **季度报告归档命名 = "可检索 + 可对照"**：文件名 `2026-Q3.md`（季度-年）；路径 `/home/ubuntu/decision-improvement/quarterly/`；本地镜像 `D:\decision-weekly\quarterly\`。**不写"复盘报告.md" / "季度总结.md"**——名字要可排序、可同比、可 grep。承自外脑 #8 第六章 6.2 命名规则的反例——"决策记录.md"是无法检索的命名失败。

9. **偏差演化是季度报告的"指纹"**：19 条高频偏差（外脑《行为纪律手册》第二章）每 12 周出现频次的分布 = 用户的"行为指纹"——例如"损失厌恶连续 12 周每周都出现 1-2 次 + 沉没成本 Q3 后半突然消失"→ 说明用户的预承诺机制开始生效（具体场景：量化项目费率套利坚持止损规则）。**指纹的演化是进步的最硬证据**——比分数曲线更难骗自己。

10. **季度报告是 v3 三件套的"系统级闭环"**：周评估（weekly_review.py）→ 单点反馈；月度对账（人工 monthly checklist）→ 跨周综合；**季度报告（quarterly_review.py）→ 系统级体检**。季度报告把 v3 三件套从"嵌入式练习"升级为"嵌入式系统"——它不是单独的步骤，是 weekly_review.py 的"上层聚合"。承自外脑《自动量化项目架构初稿》L6 监控层（信息流向 = Meadows 第 6 级杠杆）——季度报告是"信息流向"的最终汇聚点。

## 核心逻辑链

1. **前提**：决策进步线 v3（2026-08-31 上线）已经能跑通"嵌入式练习闭环"——每 30 分钟 process_inbox.py 处理飞书消息生成决策日志，每周日 weekly_review.py 汇总本周 3 维评估。**但 v3 缺季度层**——12 周的 weekly/ 各自孤立，4 维度分数只能在单周内部对比，看不到"季度趋势"和"偏差演化"。这是 v3 当前的"天花板"——每周都知道"本周 X 分"，但不知道"我是不是真的在变好"。承自外脑《认知偏差全谱》B 组"记忆的七宗罪" + G 组"情绪一致性记忆"——3 个月后回看"分数 3/3/1"会陷入"今天感觉不错就以为自己一直不错"的偏差。

2. **机制一（4 维度趋势化）**：把 weekly_review.py 的 3 维（先停 60s / 视角扩展 / 复盘固化）扩展为季度版的 4 维——增加"决策质量"作为第 4 维（基于 #6 触发场景的命中率统计）。**4 维的 12 周曲线 = 进步的可视化**——任何一维的趋势反转（连续 3 周下降 > 0.5 分）都会被自动标记为"黄色警报"，触发下一周的周评估重点观察。

3. **机制二（偏差演化的指纹化）**：每周 weekly_review.py 已经隐含偏差标注（progress_observation 字段有偏差类型），季度报告把 13 周的偏差标注合并成"19 条 × 13 周"矩阵 → 计算"每条偏差的 13 周趋势"（斜率 = 进步 / 退步 / 横盘）→ 列出"Top 3 收敛偏差"（进步最快）和 "Top 3 发散偏差"（退步最严重）→ 自动归类（收敛归功于"行为纪律机制起效" / 发散归因于"新场景未匹配去偏工具"）。

4. **机制三（决策质量的统计化）**：每条 decisions/ 都有 decision_type 字段（Cynefin 4 域），季度报告统计 12 周的决策分布（Clear / Complicated / Complex / Chaotic 各多少条）→ 计算"pre-mortem 命中率"（post-mortem 时 pre-mortem 列出的 3 个失败原因实际触发了几条 / 3）→ 计算"反向压力实际触发率"（5 条反向压力实际触发了几条 / 5）→ 用这两个率率判断"决策质量"是上升还是下降。

5. **机制四（行为纪律机制使用的可观测化）**：5 大纪律机制（外脑《行为纪律手册》第一章：预承诺 / 标准化 / 对账 / 隔离 / 复盘）每周被触发的频次从 decisions/ 推断——例如"出现'止损 / 止盈 / 退出 / 暂停'关键词 → 预承诺 1 次"；"出现'清单 / 流程 / 模板' → 标准化 1 次"。**12 周的频次分布 = 行为纪律的横截面**——"机制 A 频次突然下降"说明用户正在放松该机制（外脑 #8 复盘节奏协议的核心警告："复盘一周就停了"是常见死法）。

6. **结果**：季度报告 = 4 维趋势 + 偏差演化指纹 + 决策质量统计 + 行为纪律机制使用频次 = 一份**结构化的、可同比的、可追溯的"嵌入式系统体检报告"**。每 90 天自动生成 1 次，用户在飞书看到金色卡 → 1 分钟预览趋势 → 30 分钟精读全文 → 提取 3 条下季度锚点 → 写回 decisions/YYYY-MM/ 作为新决策的"承诺触发器"。

7. **行动指引**：① 季度最后一周日 23:00 自动跑 quarterly_review.py（cron 配置见 §5）→ ② 自动读取过去 12 周的 weekly/ + decisions/ + inbox processed → ③ 调用 MiniMax-M3 二次分析（4 维 + 偏差演化 + 决策质量 + 行为纪律）→ ④ 写 quarterly/YYYY-Qn.md + 本地镜像 → ⑤ 飞书推金色卡（标题 + 4 维总分 + Top 3 收敛偏差 + Top 3 发散偏差 + 3 条下季度锚点摘要）→ ⑥ 人工 review 3 处（趋势反转点 / 新增偏差 / 下季度锚点）→ ⑦ 人工补充 1 段"季度一句话总结" → ⑧ 下季度第 1 周日周评估时引用上季度报告的 3 条锚点作为"承诺触发器校验"。

8. **诚实声明**：本文的 quarterly_review.py 是**新增代码**——尚未在腾讯云服务器跑过；weekly_review.py / process_inbox.py 是已跑通基础（2026-08-31 上线 + 首跑 W36 验证）。本文的 LLM prompt 是**设计稿**——基于 weekly_review.py 的 system prompt 扩展，未做过 A/B。报告的"12 页结构"是**目标模板**——实际首跑可能只跑通"封面 + 4 维度"8 页，剩余 4 页是"增量演化"。所有"季度锚点"都是**示例**——首跑时由 MiniMax-M3 生成 + 人工 review。

## 分章笔记

### 第一章　季度复盘的 5 大目标（vs 周复盘的差异）

> **核心论证**：周复盘看"点"，季度复盘看"面"；周复盘看"做了什么"，季度复盘看"是不是在变好"。这两者不能互相替代——周复盘再细，没有季度层的趋势聚合就看不到进步曲线；季度报告再全，没有周复盘的逐周数据就追溯不到"为什么这样"。

#### 1.1 季度复盘 vs 周复盘的 5 大差异

| 维度 | 周复盘（weekly_review.py） | 季度复盘（quarterly_review.py） | 季度独有的价值 |
| --- | --- | --- | --- |
| **时间窗** | 7 天（周一 ~ 周日） | 90 天（约 13 周） | 季度视角才能看到"3 周趋势 ≠ 1 周噪声" |
| **数据源** | decisions/ 本周（3-5 条） | weekly/ 13 篇 + decisions/ 全季 + inbox processed | 多数据源交叉验证更准 |
| **评估深度** | 3 维（先停 60s / 视角扩展 / 复盘固化） | 4 维（+ 决策质量） | 决策质量是周维度无法独立衡量的 |
| **输出长度** | 400-600 字 + 飞书紫卡 | 3000-5000 字 + 12 页结构 + 飞书金卡 | 长度 = 信息密度，不是冗余 |
| **阅读场景** | 周日晚精读 5 分钟 | 季度末工作日精读 30 分钟 | 工作日 = 决策多，更需要"系统级体检" |

#### 1.2 季度复盘的 5 大目标（量化"什么算做好"）

**目标 1：可观测的趋势识别（必须）**

定义：4 维度（先停 60s / 视角扩展 / 复盘固化 / 决策质量）各自画出 13 周曲线，任何维度连续 3 周下降 > 0.5 分触发"黄色警报"，需要人工复盘。

验收标准：报告里能看到 4 张图（每维度一张折线图 + 黄色警报标记），即使没图表也至少有"维度 X：趋势上升 / 下降 / 横盘，证据是 12 周均值从 X 升到 Y"。

**目标 2：偏差演化的指纹化（必须）**

定义：19 条高频偏差（外脑《行为纪律手册》第二章）每 13 周出现频次 = "偏差指纹"，Top 3 收敛偏差和 Top 3 发散偏差必须明确列出。

验收标准：报告有"Top 3 收敛偏差"小节（说明该偏差从 X 次/周降到 Y 次/周，归功于什么机制）+ "Top 3 发散偏差"小节（说明该偏差从 X 次/周升到 Y 次/周，触发场景是什么）。

**目标 3：决策质量的统计化（必须）**

定义：12 周的 decisions/ 按 Cynefin 4 域分类统计 + pre-mortem 命中率 + 反向压力实际触发率，给出"决策质量总分"（百分位）。

验收标准：报告有"决策质量"章节，给出 4 域分布百分比 + pre-mortem 命中率（实际触发失败原因 / 列出的失败原因）+ 决策质量总分。

**目标 4：行为纪律机制使用的可观测化（必须）**

定义：5 大纪律机制（预承诺 / 标准化 / 对账 / 隔离 / 复盘）每周触发频次 = "机制使用曲线"。

验收标准：报告有"机制使用频次"章节，给出每机制的 12 周触发次数 + 总趋势 + "最弱机制"（频次最低的那个机制，需要下季度加强）。

**目标 5：下季度锚点的可执行化（必须）**

定义：基于上述 4 个目标，自动生成 3 条具体可执行的"下季度锚点"——不是"努力改进"这种空话，是"每周日周评估时检查 X 频次"这种具体动作。

验收标准：报告最后一页"下季度锚点"有 3 条，每条满足"具体 + 可观测 + 1 季度内能验证"。

#### 1.3 季度复盘的"反目标"（什么不做）

承自外脑《反脆弱决策清单》#6 §5 via negativa——"减法优先"：

- **不重写周评估**：季度报告是周评估的"上层聚合"，不是替代。任何"重新评估本周"在季度报告里都不该出现——那是 weekly_review.py 的活。
- **不预测下季度**：季度报告只总结过去 12 周 + 给 3 条锚点，不预测下季度的具体分数曲线——预测属于"决策记录模板 #8"的"复盘节奏协议"，不是季度报告的活。
- **不直接做决策**：季度报告不能"建议某项投资 / 某次跳槽"——它是"系统级体检报告"，不是"决策建议书"。用户读到报告后的"做什么"是"决策日志"的新条目，由 v3 三件套继续捕获。

#### 1.4 季度复盘的"边界"（边界感 = 反脆弱）

| 边界类型 | 边界内容 | 触发动作 |
| --- | --- | --- |
| **时间边界** | 严格 12 周（不是 11 周也不是 14 周） | 多 1 周 / 少 1 周都重算 |
| **数据边界** | 3 数据源（weekly + decisions + inbox processed）必须齐全 | 缺 1 个数据源 → 报告标注"数据不全" |
| **LLM 边界** | 单次 prompt 输入 ≤ 30KB；输出 ≤ 4096 tokens | 超过 → 截断 + 标注"摘要非全文" |
| **人工边界** | 3 处必须人工 review（趋势反转 / 新增偏差 / 下季度锚点） | 跳过 → 报告标注"未人工 review" |
| **推送边界** | 季度末最后一周日 23:00 推金色卡（不早不晚） | 错峰不撞周日 22:00 weekly_drill + 22:30 weekly_review |

### 第二章　数据源：12 周的 weekly/ + decisions/ + 飞书交互历史

> **设计原则**：3 个数据源必须并联——任何一个缺失都会让季度报告退化成"周评估 ×13"。承自外脑《行为纪律手册》机制 3"对账"——"实际结果"和"事先预期"做定期比对，识别偏差漂移，是机制的反馈回路；季度报告就是把"反馈回路"的频率从"每周"升级到"每季度"。

#### 2.1 数据源 1：weekly/（12-13 个 MD 文件）

**路径**：
- 服务器：`/home/ubuntu/decision-improvement/weekly/`
- 本地镜像：`D:\decision-weekly\`（注：v3 已有 weekly/ 目录命名，但本地目前还没镜像目录——需要建 `D:\decision-weekly\quarterly\` 子目录）

**文件格式**：`{year}-W{week:02d}.md`（如 `2026-W36.md`），由 weekly_review.py 生成。

**每篇内容**：周评估正文 + 本周决策日志清单（承自 weekly_review.py 的输出格式）：
- 周评估正文：先停 60s / 视角扩展 / 复盘固化 3 维评分（1-5 分）+ 证据 + 改进建议 + 下周行动锚点（3 条）
- 本周决策日志清单：`- 2026-MM-DD: 2026-MM-DD-HH-MM-SS-om_xxx.md`

**季度报告读取策略**：
- 读取过去 13 个 ISO 周（即"季度最后一周日"往前推 12 周 = 13 周，因为 quarterly_review.py 在第 13 周周日跑，本周数据已包含）
- 每篇截断到 2000 字节（13 篇 ≈ 26KB，正好在 LLM 输入预算内）
- 优先保留 3 维分数段 + 行动锚点段 + 决策日志清单段（去掉证据展开段，因为 LLM 看证据原文会失焦）

#### 2.2 数据源 2：decisions/（季度所有 MD 文件）

**路径**：
- 服务器：`/home/ubuntu/decision-improvement/decisions/YYYY-MM/`
- 本地镜像：`D:\decision-log\YYYY-MM\`（已有 2026-08 / 2026-09 等月目录）

**文件格式**：`{YYYY-MM-DD-HH-MM-SS}-{om_xxx}.md`，由 process_inbox.py 生成。

**每篇内容**（承自 process_inbox.py 输出）：
- 元信息：消息 ID + 发送者 + 接收时间
- 原消息：飞书原始 content
- LLM 总结：决策点 / 外脑引用 / 进步线观察 / 行动锚点 4 行（150-250 字）
- 文件尾：process_inbox.py 自动生成的 footer

**季度报告读取策略**：
- 读取过去 13 周（约 90 天）所有 .md
- 按月分组统计：每月 X 条 → 季度总计 ≈ 39-65 条（每周 3-5 条 × 13 周）
- **优先级过滤**：保留 `progress_observation` 字段含"偏差名"（如"锚定 / 损失厌恶 / 沉没成本"）的条目
- 每条截断到 800 字节（类似 process_inbox.py 的截断策略）
- 过滤后约 30-50 条 × 800 字节 ≈ 24-40KB，超 LLM 输入预算 → 进一步按"偏差标注数 ≥ 2"过滤到 15-20 条 ≈ 12-16KB

#### 2.3 数据源 3：飞书交互历史（inbox processed JSON）

**路径**：
- 服务器：`/home/ubuntu/decision-improvement/inbox/processed/`
- receiver.py 写入；process_inbox.py 处理后移到 processed/

**文件格式**：`{YYYY-MM-DD-HH-MM-SS}-{message_id}.json`

**每条 JSON 字段**：
- `message_id`：飞书消息唯一 ID
- `content`：用户原文
- `received_at`：接收时间（ISO 格式）
- `sender_open_id`：发送者
- `llm_feedback`：receiver.py v3 的 LLM 反馈（如有，含"评分 + 盲区 + 行动建议"）

**季度报告读取策略**：
- 读取过去 13 周所有 .json
- 按 decision-type 过滤：保留"非 idle / 非闲聊"的内容（即有实际决策的）
- 每条只读 `content` + `received_at` 两个字段，截断到 200 字节
- 过滤后约 50-80 条 × 200 字节 ≈ 10-16KB

#### 2.4 数据源整合策略（3 源合并 + LLM 输入预算）

**优先级排序**：
1. weekly/ 全文（13 篇 × 2KB = 26KB）—— 包含每周总分 + 行动锚点，最结构化
2. decisions/ 偏差标注 ≥ 2 的（15-20 条 × 800B = 12-16KB）—— 包含偏差细节
3. inbox processed 非 idle 的（50-80 条 × 200B = 10-16KB）—— 包含原始决策上下文

**总输入预算 ≈ 48-58KB**——超 LLM 安全窗口（30KB），必须**分 3 次调用**：

| 调用 | 输入 | 用途 | max_tokens |
| --- | --- | --- | --- |
| 调用 1 | weekly/ 全部 + decisions/ 偏差标注 ≥ 2 | 进步线趋势 + 决策质量 + 行为纪律机制使用 | 2500 |
| 调用 2 | inbox processed 非 idle | 偏差演化的原始证据 | 2000 |
| 调用 3 | 调用 1 + 调用 2 摘要 + 行为纪律机制使用统计 | 下季度锚点生成 | 1500 |

**调用 3 的输入是关键**——它接收调用 1 + 调用 2 的"摘要 + 关键统计"，不是原始数据；这样 LLM 可以聚焦"下一步做什么"，而不是淹没在原始数据里。

#### 2.5 数据缺失的容错

| 缺失数据源 | 报告行为 |
| --- | --- |
| weekly/ 完全缺失（如用户跑了 weekly_review.py 但未保存） | 报告顶部加红色横幅"⚠️ weekly/ 数据缺失，仅基于 decisions + inbox 评估" |
| decisions/ 完全缺失 | 报告改为"基于 weekly/ 评估"，但 4 维中的"决策质量"标"无法评估" |
| inbox processed 完全缺失 | 报告"偏差演化指纹"章节标"数据不全"，降级为"基于 weekly 标注的偏差" |
| 部分缺失（如某周 weekly 未跑） | 该周标"未评估"，不参与曲线绘制 |

### 第三章　汇总算法：4 大维度（进步线趋势 / 偏差演化 / 决策质量 / 行为纪律机制使用）

> **设计原则**：4 维度是季度报告的"四把尺子"——任何一把缺失都看不到那一面。承自外脑 #8 第五章"复盘节奏协议"——1 周 / 1 月 / 3 月 / 1 年的不同节奏对应不同检查清单；季度 = 3 月节奏的工程化产物。

#### 3.1 维度 1：进步线趋势（v3 周评估的 3 维聚合）

**输入**：weekly/ 全部 13 篇（每周 3 维分数）

**算法**：
```python
# quarterly_review.py 关键函数（伪代码）
def trend_dimension(weekly_files):
    """3 维 × 13 周 → 趋势分析"""
    trends = {
        '先停 60s': [],
        '视角扩展': [],
        '复盘固化': []
    }
    for wf in weekly_files:
        wk = parse_weekly(wf)  # 提取 3 维分数
        for dim in trends:
            trends[dim].append((wk['week_num'], wk['scores'][dim]))

    result = {}
    for dim, points in trends.items():
        scores = [s for _, s in points]
        mean = sum(scores) / len(scores)
        # 简单线性回归斜率
        slope = linear_slope(points)  # 周 vs 分数
        # 趋势反转点检测
        reversals = detect_reversals(points, window=3, threshold=0.5)
        result[dim] = {
            'mean': mean,
            'slope': slope,  # > 0 上升 / < 0 下降 / ≈ 0 横盘
            'reversals': reversals,  # 黄色警报点
            'curve': points  # 13 周曲线
        }
    return result
```

#### 3.2 维度 2：偏差演化指纹（19 条高频偏差的 13 周分布）

```python
def bias_dimension(weekly_files, decision_files):
    """19 条高频偏差 × 13 周 → 偏差指纹"""
    # 19 条高频偏差（外脑《行为纪律手册》第二章）
    bias_names = [
        '损失厌恶', '沉没成本', '处置效应', '锚定', '框架效应',
        '现状偏差', '确认偏差', '可得性', '过度自信', '乐观偏差',
        '规划谬误', '禀赋效应', '自我服务偏差', '后见之明',
        '达克效应', '锚定+调整不足', '锚定+过度自信链',
        '情绪一致性记忆', '影响启发式'
    ]
    # 初始化 19 × 13 矩阵
    matrix = {b: [0]*13 for b in bias_names}

    # 扫 weekly（每周每维度的 progress_observation）
    for i, wf in enumerate(weekly_files):
        wk = parse_weekly(wf)
        observations = wk.get('progress_observation', '')
        for bias in bias_names:
            if bias in observations:
                matrix[bias][i] += 1

    # 扫 decisions（每条 progress_observation 偏差标注）
    for df in decision_files:
        d = parse_decision(df)
        obs = d.get('progress_observation', '')
        for bias in bias_names:
            if bias in obs:
                # 映射到 ISO 周
                week_idx = iso_week_to_index(d['date'])
                matrix[bias][week_idx] += 1

    # Top 3 收敛偏差（前 6 周均值 - 后 6 周均值 > 0.5）
    converged = []
    for bias in bias_names:
        first_half = sum(matrix[bias][:6]) / 6
        second_half = sum(matrix[bias][6:]) / 6
        if first_half - second_half > 0.5:
            converged.append((bias, first_half, second_half, first_half - second_half))

    # Top 3 发散偏差（后 6 周 - 前 6 周 > 0.5）
    diverged = []
    for bias in bias_names:
        first_half = sum(matrix[bias][:6]) / 6
        second_half = sum(matrix[bias][6:]) / 6
        if second_half - first_half > 0.5:
            diverged.append((bias, first_half, second_half, second_half - first_half))

    return matrix, converged, diverged
```

**输出**：
- 19 条 × 13 周矩阵（ASCII 图 / matplotlib 热力图）
- Top 3 收敛偏差（进步） + 归因（哪个机制起效）
- Top 3 发散偏差（退步） + 触发场景

#### 3.3 维度 3：决策质量（6 类触发器占比 + pre-mortem 命中率 + 反向压力实际触发率）

**输入**：decisions/ 全部

**算法**：
```python
def decision_quality_dimension(decision_files):
    """决策质量 = 4 域分布 + pre-mortem 命中率 + 反向压力触发率"""
    domain_count = {'Clear': 0, 'Complicated': 0, 'Complex': 0, 'Chaotic': 0}
    pre_mortem_hit = 0  # pre-mortem 命中的次数
    pre_mortem_total = 0  # 有 pre-mortem 的决策总数
    reverse_pressure_trigger = 0  # 反向压力实际触发的次数
    reverse_pressure_total = 0  # 有反向压力的决策总数

    for df in decision_files:
        d = parse_decision(df)
        # Cynefin 域分布
        dt = d.get('decision_type', 'Unknown')
        if dt in domain_count:
            domain_count[dt] += 1

        # pre-mortem 命中率（基于外脑 #8 第十一章 5.4 复盘节奏协议）
        pre = d.get('pre_mortem', [])
        if pre:
            pre_mortem_total += 1
            actual_failures = d.get('actual_failures_1y', [])
            if any(f in actual_failures for f in pre):
                pre_mortem_hit += 1

        # 反向压力实际触发率
        rp = d.get('reverse_pressure', [])
        if rp:
            reverse_pressure_total += 1
            if d.get('rp_triggered', False):
                reverse_pressure_trigger += 1

    # 决策质量总分（百分位）
    hit_rate = pre_mortem_hit / pre_mortem_total if pre_mortem_total > 0 else 0
    rp_rate = reverse_pressure_trigger / reverse_pressure_total if reverse_pressure_total > 0 else 0
    # 加权（命中率 60% + 反向压力 40%）
    quality_score = (hit_rate * 60 + rp_rate * 40)

    return {
        'domain_distribution': domain_count,
        'pre_mortem_hit_rate': hit_rate,
        'reverse_pressure_trigger_rate': rp_rate,
        'quality_score': quality_score
    }
```

**输出**：
- 4 域分布饼图（Clear / Complicated / Complex / Chaotic 各占比）
- pre-mortem 命中率（%）
- 反向压力实际触发率（%）
- 决策质量总分（0-100 百分位）

#### 3.4 维度 4：行为纪律机制使用频次（5 大机制 × 13 周）

```python
def discipline_dimension(weekly_files, decision_files):
    """5 大纪律机制 × 13 周 → 机制使用曲线"""
    mechanisms = {
        '预承诺': ['止损', '止盈', '退出', '暂停', '承诺', '触发器', '阈值'],
        '标准化': ['清单', '流程', '模板', '决策树', '规则', '标准'],
        '对账': ['复盘', '对账', '回顾', '校准', '反馈', '对比'],
        '隔离': ['冷静期', '24小时', '推迟', 'sleep on it', '冷却'],
        '复盘': ['复盘', '决策记录', 'pre-mortem', 'AAR', '回顾']
    }
    # 初始化 5 × 13 矩阵
    matrix = {m: [0]*13 for m in mechanisms}

    for i, wf in enumerate(weekly_files):
        content = open(wf, encoding='utf-8').read()
        for m, kws in mechanisms.items():
            for kw in kws:
                if kw in content:
                    matrix[m][i] += 1
                    break  # 每周每机制最多 +1

    for df in decision_files:
        content = open(df, encoding='utf-8').read()
        week_idx = iso_week_to_index(parse_date_from_filename(df))
        for m, kws in mechanisms.items():
            for kw in kws:
                if kw in content:
                    matrix[m][week_idx] += 1
                    break

    # 最弱机制（频次最低）
    total = {m: sum(matrix[m]) for m in mechanisms}
    weakest = min(total, key=total.get)

    return matrix, total, weakest
```

#### 3.5 4 维度的交叉验证（一致性检查）

**关键**（承自外脑《行为纪律手册》第五章"去偏失败"）：单一去偏工具对复合偏差常常无效。4 维度不能孤立解读，必须交叉：

| 交叉模式 | 解读 |
| --- | --- |
| 进步线趋势上升 + 决策质量下降 | 进步可能"流于形式"——周评估分数在涨，但 pre-mortem 命中率没涨 |
| 偏差收敛 + 行为纪律机制频次下降 | 偏差收敛可能"自然回归"而非机制起效 |
| 行为纪律机制频次稳定 + 偏差发散 | 机制在使用但无效——需要换工具 |
| 决策质量上升 + 偏差发散 | 决策在变好但用户变浮躁——可能"过度自信" |

#### 3.6 4 维度的总分（季度总分计算）

**总分公式**（简单加权）：
```
季度总分 = 进步线趋势均值 × 0.25 + 偏差收敛度 × 0.25 + 决策质量 × 0.30 + 行为纪律机制使用健康度 × 0.20
```

- 进步线趋势均值：3 维各 1-5 分，均值后乘以 20 转为百分位
- 偏差收敛度：(1 - 发散偏差占比) × 100

#### 5.2 核心函数设计

**函数 1：get_quarter_dates()**
```python
def get_quarter_dates(now_dt):
    """返回 (quarter_num, year, start_date, end_date)
    例：2026-09-27 → (3, 2026, '2026-07-01', '2026-09-30')
    """
    year = now_dt.year
    quarter = (now_dt.month - 1) // 3 + 1
    start_month = (quarter - 1) * 3 + 1
    end_month = quarter * 3
    start = datetime(year, start_month, 1)
    # 季度最后一天
    if end_month == 12:
        end = datetime(year, 12, 31)
    else:
        end = datetime(year, end_month + 1, 1) - timedelta(days=1)
    return quarter, year, start.strftime('%Y-%m-%d'), end.strftime('%Y-%m-%d')
```

**函数 2：collect_quarter_data()**
```python
def collect_quarter_data(start_date, end_date):
    """收集 3 数据源（weekly + decisions + inbox processed）
    每个数据源返回 (files, sizes, total_bytes)
    """
    result = {}

    # weekly/ 全部（13 篇）
    weekly_files = []
    if os.path.isdir(WEEKLY_DIR):
        for fn in sorted(os.listdir(WEEKLY_DIR)):
            if not fn.endswith('.md'):
                continue
            full = os.path.join(WEEKLY_DIR, fn)
            weekly_files.append(full)
    # 截断每篇到 2000 字节
    weekly_content = []
    for wf in weekly_files[-13:]:  # 最近 13 篇
        with open(wf, 'r', encoding='utf-8') as f:
            content = f.read()[:2000]
        weekly_content.append((wf, content))
    result['weekly'] = weekly_content

    # decisions/ 全部（按日期过滤 + 关键词过滤）
    decision_files = []
    if os.path.isdir(DECISIONS_DIR):
        for month_dir in sorted(os.listdir(DECISIONS_DIR)):
            full_month = os.path.join(DECISIONS_DIR, month_dir)
            if not os.path.isdir(full_month):
                continue
            # 检查 month_dir 是否在季度范围内
            month_num = int(month_dir.split('-')[1]) if '-' in month_dir else 0
            year_num = int(month_dir.split('-')[0]) if '-' in month_dir else 0
            quarter_months = []
            for q, ms in QUARTER_MONTHS.items():
                if month_num in ms and year_num == now_dt.year:
                    quarter_months = ms
                    break
            if month_num not in quarter_months:
                continue
            for fn in sorted(os.listdir(full_month)):
                if not fn.endswith('.md'):
                    continue
                full = os.path.join(full_month, fn)
                decision_files.append(full)
    # 优先级过滤：保留含偏差标注 ≥ 2 的
    decision_priority = []
    for df in decision_files:
        with open(df, 'r', encoding='utf-8') as f:
            content = f.read()
        bias_count = sum(1 for b in BIAS_NAMES if b in content)
        if bias_count >= 2:
            decision_priority.append((df, content[:800]))
    # 限制到 MAX_DECISION_SAMPLE 条
    decision_priority = decision_priority[:MAX_DECISION_SAMPLE]
    result['decisions'] = decision_priority

    # inbox/processed/ 全部（按日期过滤 + decision-type 过滤）
    inbox_files = []
    if os.path.isdir(INBOX_PROCESSED_DIR):
        for fn in sorted(os.listdir(INBOX_PROCESSED_DIR)):
            if not fn.endswith('.json'):
                continue
            full = os.path.join(INBOX_PROCESSED_DIR, fn)
            try:
                with open(full, 'r', encoding='utf-8') as f:
                    msg = json.load(f)
                content = msg.get('content', '')
                received_at = msg.get('received_at', '')
                # 跳过 idle / 闲聊（启发式：content < 20 字 = 闲聊）
                if len(content) < 20:
                    continue
                inbox_files.append((full, content[:200], received_at))
            except Exception:
                continue
    # 限制到 MAX_INBOX_SAMPLE 条
    inbox_files = inbox_files[:MAX_INBOX_SAMPLE]
    result['inbox'] = inbox_files

    return result
```

**函数 3：call_minimax_3phase()**
```python
def call_minimax_3phase(weekly_data, decisions_data, inbox_data):
    """3 次 LLM 调用：调用1（4维主体）+ 调用2（偏差细化）+ 调用3（下季度锚点）
    返回 (call1_result, call2_result, call3_result)
    """
    # 调用 1：基于 weekly + decisions 评 4 维
    user_msg_1 = build_msg_4dimensions(weekly_data, decisions_data)
    # 输入大小检查
    if len(user_msg_1.encode('utf-8')) > MAX_LLM_INPUT_BYTES:
        # 进一步截断
        user_msg_1 = user_msg_1[:MAX_LLM_INPUT_BYTES].decode('utf-8', errors='ignore')
    call1, err1 = call_minimax(user_msg_1, max_tokens=2500)

    # 调用 2：基于 inbox 评偏差演化
    user_msg_2 = build_msg_bias(inbox_data, call1)  # call1 作为上下文
    if len(user_msg_2.encode('utf-8')) > MAX_LLM_INPUT_BYTES:
        user_msg_2 = user_msg_2[:MAX_LLM_INPUT_BYTES].decode('utf-8', errors='ignore')
    call2, err2 = call_minimax(user_msg_2, max_tokens=2000)

    # 调用 3：基于调用 1+2 生成下季度锚点
    user_msg_3 = build_msg_anchors(call1, call2)
    if len(user_msg_3.encode('utf-8')) > MAX_LLM_INPUT_BYTES:
        user_msg_3 = user_msg_3[:MAX_LLM_INPUT_BYTES].decode('utf-8', errors='ignore')
    call3, err3 = call_minimax(user_msg_3, max_tokens=1500)

    return (call1, call2, call3), (err1, err2, err3)
```

#### 5.4 故障模式与兜底

**故障 1：LLM 调用失败**

#### 6.4 Prompt 隔离与复用策略

**3 个 prompt 必须隔离**——不能合并成一个 prompt：

| Prompt | 输入 | 输出 | max_tokens |
| --- | --- | --- | --- |
| 调用 1：4 维度主体 | weekly + decisions | 4 维度评估 | 2500 |
| 调用 2：偏差细化 | 调用 1 摘要 + inbox | 偏差演化细化 | 2000 |
| 调用 3：下季度锚点 | 调用 1+2 摘要 | 3 条锚点 | 1500 |

**为什么 3 个调用而非 1 个**：
1. **上下文窗口限制**：单次调用 ≤ 30KB 输入；3 数据源总输入 ~50KB，必须分 3 次
2. **专业聚焦**：每个 prompt 只负责 1 个维度，LLM 不会被"全面评估"拖垮
3. **失败兜底**：任一调用失败不影响其他调用（故障隔离）
4. **复用基础**：调用 1 的 prompt 可独立抽出"4 维度评估器"作为通用工具

**调用链设计**：
```
调用 1 (输入: weekly + decisions)
   ↓ 输出 4 维度评估 + 关键统计
调用 2 (输入: 调用 1 摘要 + inbox)
   ↓ 输出偏差细化
调用 3 (输入: 调用 1 摘要 + 调用 2 摘要)
   ↓ 输出下季度锚点
```

#### 6.5 LLM 输出质量校验（人工 review 标记）

**3 处必须人工 review**（即使 LLM 输出没问题）：
1. **趋势反转点**（如某维度连续 3 周下降 > 0.5 分）→ 人工确认是"真退步"还是"评估标准更严"
2. **新增偏差**（前 12 周没出现、本季度新出现）→ 人工确认是"新场景触发"还是"LLM 误分类"
3. **下季度锚点**（LLM 生成的 3 条）→ 人工 confirm 是否真的"够具体 + 可观测 + 1 季度内能验证"

报告里用 ⚠️ 标记这 3 处，提醒人工必填。

### 第七章　人工干预点（哪些必须人工 review，不能全自动）

> **核心论证**：LLM 评估偏差演化、决策质量时，会因为"上下文不足"或"评估标准漂移"做出过度概括。**没有人工 review 的季度报告 = 学术论文，不是操作手册**。承自外脑《行为纪律手册》第五章"去偏失败"——"5 大机制只用 1 个"是常见死法；季度报告里"全自动 + 无人工 review"也是同源问题。

#### 7.1 3 处必须人工 review（缺一不可）

**人工 review 1：第 2 页"季度一句话总结"**

- **必填位置**：报告第 2 页整页
- **必填内容**：200 字以内，1-2 句话总结本季度"是不是在变好 + 最大进步 + 最大退步"
- **不能 LLM 自动的原因**：季度总结是"主观判断"——同样的数据，不同人解读不同；LLM 会给出"客观描述"但缺"主观意义"
- **超时处理**：报告生成后 24h 内人工未补 → 飞书红色告警"⚠️ 季度报告待人工 review"

**人工 review 2：第 8 页"Top 收敛/发散偏差归因"**

- **必填位置**：第 8 页 Top 3 收敛/发散偏差表格的"归因机制 / 触发场景"列
- **必填内容**：每条偏差的具体归因（哪种行为纪律机制起效 / 哪种场景触发）
- **不能 LLM 自动的原因**：归因需要"上下文回溯"到具体 weekly/decisions/inbox 文件，LLM 容易"过度概括"（如把"沉没成本收敛"简单归因到"标准化机制起效"，但实际可能是"项目 Phase 1 paper trading 期间天然没有沉没成本诱因"）
- **超时处理**：报告生成后 48h 内人工未补 → 飞书橙色告警"⚠️ 偏差归因待人工"

**人工 review 3：第 12 页"下季度锚点 confirm"**

- **必填位置**：第 12 页"承诺触发器"小节（不是锚点本身，LLM 已生成）
- **必填内容**：人工 confirm 3 条锚点是否"够具体 + 可观测 + 1 季度内能验证"；如有不符合的，修改或替换
- **不能 LLM 自动的原因**：锚点的"可执行性"是判断而非计算——LLM 容易给出"提升 X 维度"这种抽象建议
- **超时处理**：下季度第 1 周日周评估时强制引用 3 条锚点作为起跑线；未 confirm 的锚点不作为承诺触发器

#### 7.2 6 处可选人工 review（按需）

| 位置 | 内容 | 何时人工 review |
| --- | --- | --- |
| 第 4 页 | 维度 1 趋势判断 | 黄色警报触发时 |
| 第 5-7 页 | 维度 1 深度案例 | LLM 输出"无可观测证据"时 |
| 第 9 页 | 4 域分布合理性 | Chaotic > 20% 或 Clear > 50% 时 |
| 第 10 页 | 最弱机制判断 | 机制频次差异 > 3x 时 |
| 第 11 页 | 4 维度交叉验证关键发现 | 出现矛盾模式时（如进步上升 + 决策质量下降） |
| 季度总分 | 同环比对比 | 总分变化 > 10 分时 |

#### 7.3 人工 review 工作流（"24h / 48h / 7d" 三档）

**24h 内必填**：第 2 页"季度一句话总结"
**48h 内必填**：第 8 页"偏差归因"
**7d 内 confirm**：第 12 页"下季度锚点"

**超时兜底**（系统侧）：
```python
# quarterly_review.py 配套 cron：每 24h 检查人工 review 状态
# 0 0 * * * /usr/bin/python3 /home/ubuntu/decision-improvement/check_quarterly_review.py
# 检查报告第 2 页是否人工补全（用 sentinel 字符串 "[待人工补全]" 检测）
# 未补全 → 飞书红色告警
```

#### 7.4 人工 review 的"反偏差"自检

**人工 review 本身可能引入偏差**（外脑《认知偏差全谱》F 组"动机性推理"）：
- 自我服务偏差：人工 review 时倾向"成功归自己 / 失败归运气"
- 确认偏差：人工 review 时倾向找"支持自己既有判断"的证据
- 锚定效应：人工 review 时被 LLM 输出"锚定"，照搬 LLM 判断不二次思考

**反自检 checklist**：
- [ ] 我是否在 LLM 输出里**找反例**？（不仅看支持结论的，也看反驳结论的）
- [ ] 我是否**让对手方先讲 5 分钟**？（如有 Cherry 协作，对话中先复述反方）
- [ ] 我是否**写下"如果重新做一次，我会改什么"**？（决策记录模板 #8 偏差自检字段）
- [ ] 我是否**把人工 review 推迟 24h**？（避免"刚跑完报告情绪未冷却"的判断）
